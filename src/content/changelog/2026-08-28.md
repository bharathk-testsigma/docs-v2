## New features

**Redesigned Test Case Results** — The right pane on a failed step is now a control surface: approve an auto-healed element, compare runs, run visual analysis, or open root cause analysis without leaving the first screen.

**Root Cause Analysis on Failed Steps** — Testsigma reads the error, screenshot, page source, and any heal attempts, then explains what broke in plain language, in the Analysis tab beside Locators, Logs, Step Settings, and Metadata. Available to clients with Analyzer V2 enabled.

**Compare Runs** — Put a failing step, a whole test case, its screenshots, or its source code beside the same item from any previous run. The comparison spans adjacent steps too, since the step reporting an error often is not the one that caused it.

**Visual Analysis Overlay** — Compare the authoring-time capture against the execution-time capture as an overlay, with the two screenshots on top of each other rather than side by side.

**Locator Trace on Auto-Heal** — Every auto-heal event carries a full trace of how the engine arrived at its result and whether it succeeded, built on the new Auto Heal V2 architecture. Failed heal attempts get root cause analysis of their own.

**Salesforce on the Modern Engine** — The Modern execution engine now supports Salesforce, including Salesforce NLPs and addons, alongside Web and Unified Mobile.

**Execution Videos on Local Execution** — Local runs now record execution video, so a failure can be reviewed visually instead of pieced together from screenshots.

**Export Test Reports via REST API** — Export a report as XML, PDF, or Excel at any level: a whole test plan run, one machine, one suite, or a single test case. Generation is asynchronous — trigger it, poll the same endpoint until the status reads SUCCESS, then download from the returned link.

## Improvements

**Auto-Heal Approve or Reject In Place** — Accept or reject a healed element from the first screen, with Update Element to correct a locator by hand and Relearn Step to re-capture it.

**Test Data Names in Reports** — Data-driven test cases now report the Test Data Profile and Test Data Set used for each iteration, at test case level.

**Reports Reflect Run-Time Names** — Plan, suite, case, environment, machine, and data profile names now appear as they were when the run happened, so renaming or deleting an item no longer rewrites older reports.

**Resizable Result Panes** — A splitter between the step list and the detail pane lets you size each to the failure you are reading.

**Plan Availability Is Visible** — An upgrade icon now marks any feature or preference that is not part of the current plan, and AI feature toggles moved into Settings > Preferences.

**PDF Screenshot Controls** — Choose which screenshots a PDF report carries — all, failed only, or none — and whether they render at low or high resolution.
