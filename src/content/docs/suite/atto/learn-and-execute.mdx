Atto has two ways to put an agent on your live application, and they are not interchangeable. Agentic Learning (Beta) starts from manual steps and writes the automation. Run with Copilot starts from automation that already exists and verifies it.

## Choosing between them

The input decides which one you want. If you have prose steps a human wrote, you need Agentic Learning (Beta). If you have generated steps that need checking, you need Run with Copilot.

| | Agentic Learning (Beta) | Run with Copilot |
| --- | --- | --- |
| Input | Manual steps | Automated NLP steps |
| What the agent does | Drives the application, then generates automation from what it observed | Executes the steps and updates locators |
| Your role | Record manual steps when the agent gets stuck | Set debug points, pause, and record |
| Output | A new automated test case | A verified or updated test case |

Both open a Copilot window beside the test case, and both drive Chrome for Testing rather than your everyday browser.

## How Agentic Learning works

You start the agent, and it works through your manual steps against the running application. The chat log records each step with its verdict, and a green tick marks the ones that passed.

The agent is not locked to its own session. You keep full access to the application in the browser throughout, so when the agent stalls you can drive the application yourself and let it pick up from there. **Record Manual Steps** is the control for that.

When the manual steps are done, you ask Atto to generate the automated test case. It produces NLP steps bound to Testsigma element names, which you then save to the library.

<Aside type="note">
Agentic Learning is Beta as of July 2026. Verify the flow in the product before you build a process around it.
</Aside>

## How Run with Copilot works

Run with Copilot executes automated steps that Atto generated and repairs them as it goes. Its distinguishing control is **Generate Steps** in the Copilot panel header, which fills in automation mid-session when a locator is missing or a step fails.

After the run, a banner reports that the steps may have changed and offers a refresh. Take it: the test case in front of you is stale until you do.

## Where Copilot fits

Plain Copilot is the third member of this family and the one people confuse with the other two. It executes the steps of a test case you already have, pauses at debug points, and records new steps live while paused. It does not generate a test case from scratch. [Copilot Mode](/suite/atto/copilot/) documents that session end to end.

All three need Testsigma Terminal running locally. Copilot cannot start without it, and the product says so rather than failing quietly.

## FAQs

**Can I run the old Java agent and Testsigma Terminal on the same machine?**

Only one agent can be active at a time. Testsigma Terminal detects an existing Java agent and uses it for Copilot and for test execution.

**Which agent handles remote executions and ad-hoc runs?**

The same one. Testsigma Terminal integrates with the existing agent, and that agent serves remote executions, ad-hoc runs, and Copilot alike.

**Can I start, stop, or restart the agent from Suite?**

Not yet. The agent is managed from the Testsigma Terminal desktop application only.
