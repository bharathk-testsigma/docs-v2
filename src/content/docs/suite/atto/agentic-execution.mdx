Atto has two ways to put an agent on your live application, and they are not interchangeable. Agentic Learning (Beta) starts from manual steps and writes the automation. Run with Copilot starts from automation that already exists and verifies it.

## Choosing between them

The input decides which one you want. If you have prose steps a human wrote, you need Agentic Learning (Beta). If you have generated steps that need checking, you need Run with Copilot.

| | Agentic Learning (Beta) | Run with Copilot |
| --- | --- | --- |
| Primary goal | Discover and correct the test flow | Execute and validate the generated steps |
| Input | Manual steps | Automated NLP steps |
| What the agent does | Explores the application, then generates automation from what it observed | Executes the steps, verifies they work, and updates locators |
| When it runs | During test generation and learning | After generation, before the test case is saved |
| Your role | Mostly autonomous; record manual steps when the agent gets stuck | Interactive debugging and validation |
| Output | A refined, complete flow as a new automated test case | A verified or updated test case, ready for execution |

Both open a Copilot window beside the test case, and both drive Chrome for Testing rather than your everyday browser.

## How Agentic Learning works

Agentic Learning identifies the correct test flow when information is missing or incorrect. It behaves like an exploratory tester: it learns the application's behavior and adjusts the test case to match the actual user journey. Use it to:

- Identify application navigation paths.
- Locate and add missing steps to the test flow.
- Correct steps that deviate from the expected workflow.
- Learn common behavior patterns within the application.

Reach for it when generated flows are incomplete, steps are missing or in the wrong order, or the navigation path is unclear.

You start the agent, and it works through your manual steps against the running application. The chat log records each step with its verdict, and a green tick marks the ones that passed.

The agent is not locked to its own session. You keep full access to the application in the browser throughout, so when the agent stalls you can drive the application yourself and let it pick up from there. **Record Manual Steps** is the control for that.

When the manual steps are done, you ask Atto to generate the automated test case. It produces NLP steps bound to Testsigma element names, which you then save to the library.

<Aside type="note">
Agentic Learning is Beta as of July 2026. Verify the flow in the product before you build a process around it.
</Aside>

## How Run with Copilot works

Run with Copilot validates a generated test case through real-time execution in a selected environment. Use it to:

- Execute generated test steps and identify failures.
- Identify issues with element detection.
- Validate that assertions and test data are correct.
- Debug steps before saving the test case to the library.

Reach for it to confirm a test runs from start to finish: no errors, every page element identified, and the test data working in that specific environment.

It executes the automated steps Atto generated and repairs them as it goes. Its distinguishing control is **Generate Steps** in the Copilot panel header, which fills in automation mid-session when a locator is missing or a step fails.

After the run, a banner reports that the steps may have changed and offers a refresh. Take it: the test case in front of you is stale until you do.

## Where Copilot fits

Plain Copilot is the third member of this family and the one people confuse with the other two. It executes the steps of a test case you already have, pauses at debug points, and records new steps live while paused. It does not generate a test case from scratch. [Copilot](/suite/test-management/test-authoring/copilot/) documents that session end to end.

All three need Testsigma Terminal running locally. Copilot cannot start without it, and the product says so rather than failing quietly.


## FAQs

**Can I run the old Java agent and Testsigma Terminal on the same machine?**

Only one agent can be active at a time. Testsigma Terminal detects an existing Java agent and uses it for Copilot and for test execution.

**Which agent handles remote executions and ad-hoc runs?**

The same one. Testsigma Terminal integrates with the existing agent, and that agent serves remote executions, ad-hoc runs, and Copilot alike.

**Can I start, stop, or restart the agent from Suite?**

Not yet. The agent is managed from the Testsigma Terminal desktop application only.
