Copilot Mode turns a test case into a live session. You launch it from the test case editor, and Copilot runs your steps in a real browser. Execution pauses where you tell it to, and you record, edit, and reorder steps without leaving.

## What Copilot does

A Copilot session merges authoring, execution, and debugging into one loop.

| Capability | What it gives you |
| --- | --- |
| Record steps | Captures interactions from a live browser and converts them into executable steps. Each recorded step runs and validates during the same session |
| Debug points | Pauses the test at a step you choose. Add or remove them before or during a run, inspect the application while paused, and adjust upcoming steps |
| Debug toolbar | A global bar with **Pause**, **Resume**, **Step Over**, **Skip Over**, and **Restart Execution** |
| Execute from step | Runs from one step instead of the whole case. Prior steps are marked **Skipped** |
| In-session step management | Add, edit, delete, reorder, and bulk-update steps inside the session |

Copilot rebuilds the execution flow whenever you change a step, so the run stays continuous.

<Aside type="note">
Copilot Mode is not the same as Copilot inside the recorder. The recorder's panel proposes whole scenarios for the page you are on — see [Author tests](/suite/web/tests/author-tests/#generate-steps-with-copilot). Copilot Mode runs an existing test case.
</Aside>

<Prerequisites>

- A test case exists.
- [Testsigma Terminal](/suite/installation/testsigma-terminal/) is installed and running.
- The Terminal dashboard shows a green dot for your application type.

</Prerequisites>

<Aside type="note">
Copilot cannot start unless Testsigma Terminal is running. Without it you get `Testsigma Terminal must be running on your desktop to use the Copilot.`, plus a **Launch Terminal** button. Auto-launch needs Terminal 2.2.2 or later.
</Aside>

## Launch a session

<Steps>

1. **Open a test case** — Go to **Create Tests → Test Cases**. Open an existing case or create one.

2. **Open Copilot** — Click **Copilot** in the **Action Panel**.

3. **Set the first pause** — In **Set Initial Debug Point**, pick the step where execution should stop.

4. **Pick a starting step** — Optionally set **Execute from Step**. Every earlier step is skipped.

5. **Choose an environment** — Set **Environment**, and use **Manage Variables** if the run needs them.

6. **Adjust the run** — Set **Additional Settings** and **Desired Capabilities** if needed.

7. **Start it** — Click **Launch** and wait for the session.

</Steps>

<Aside type="note">
**Execute from Step** does not set up your application for you. Put the application on the screen that the starting step expects, or that step fails.
</Aside>

The launch panel reports **Copilot is ready** with a green dot, and runs the session in **Chrome for Testing**.

### Launch settings

| Group | What it holds |
| --- | --- |
| Additional Settings | **Page Timeout** and **Step Timeout**, both 30 seconds by default, **Apply to all steps**, screenshot capture, and **Mock Server** |
| Desired Capabilities | A **Key**, **Data type**, and **Value** per capability — see [Desired capabilities](/suite/web/capabilities/) |

Click **Save configuration** to name and keep a launch setup. Loading a saved configuration turns the footer into **Update configuration** and **Save configuration**.

## Control a running test

A debug point is a checkpoint that pauses execution at a step. Set them before a session or during a run.

<Steps>

1. **Add one** — Hover the step and click the circle. It becomes a red dot.

2. **Remove one** — Click the red dot again. Execution stops pausing there.

</Steps>

The step list marks two positions. The **Debug Point** is a red dot where the run will stop. The **Execution Point** is a blue marker on the step running now.

### The debug toolbar

The toolbar is global. It activates whenever execution pauses, either at a debug point or on a failed step.

| Control | What it does | When to reach for it |
| --- | --- | --- |
| **Resume** | Continues from the next step, without restarting | You have inspected the pause and changed what you needed |
| **Pause** | Stops after the current step finishes | Something looked wrong and you want to read the screen |
| **Step Over** | Runs the current step, then pauses on the next | You want to watch the application one action at a time |
| **Skip Over** | Skips the current step and stops on the next | A step is failing and you want the run to carry on past it |
| **Restart Execution** | Clears the session and starts again from step one | Your edits were large enough that the paused state is stale |
| **Rec** | Records new steps live — see [Record steps](#record-steps-into-the-session) | You want to capture the fix rather than type it |

A fix does not cost you a fresh run. Pause, change the step, resume, and validate it in the same session.

## Record steps into the session

Copilot converts actions in your application into steps as you perform them. New steps run in the same session.

<Aside type="note">
**Rec** is enabled only when execution is paused at a debug point, has failed, or has finished.
</Aside>

### Record below a step

<Steps>

1. **Pick the position** — Hover a step, click **Step Below**, then click **Rec**.

2. **Use your application** — Copilot records each action as a step in real time.

3. **Stop** — Click **Stop Recording**.

4. **Review** — Read the recorded steps in the steps panel.

5. **Keep or drop them** — Click **Add Steps** to insert them below the step you picked, or **Discard** to throw them away.

</Steps>

Steps added below the last executed step run automatically. Steps added above it need **Resume**.

### Record at the end

<Steps>

1. **Start recording** — With the run paused or finished, click **Rec**. Steps land at the end by default.

2. **Use your application** — Each action becomes a step.

3. **Stop** — Click **Stop Recording** and review the panel.

4. **Append them** — Click **Add Steps**, or **Discard** to drop them.

5. **Carry on** — Click **Resume**.

</Steps>

If the run had already finished, **Add Steps** executes the new steps straight away.

<Aside type="note">
Resuming after an edit can raise the **Browser State Changed** dialog. **Restart Execution** runs the case again from the top. **Dismiss** continues from where the run stopped — then set your application to match the next step yourself.
</Aside>

## Add a step by describing it

Type what you want and Copilot offers matching NLPs.

<Steps>

1. **Open an editor** — Click **+Add new step** to append, or hover a step and click **Step Below** to insert.

2. **Describe the step** — Start typing to see matching NLPs, then select one and configure it.

3. **Fill it in** — Add the elements and test data it needs, then click **Create Step**.

</Steps>

## Edit a step

### Swap or relearn an element

Hover the step and click the element to open its menu.

| Option | What it does |
| --- | --- |
| **Rename** | Changes the display name only, leaving the locator alone |
| **Learn** | Re-records the element live so Copilot can find it on screen |
| **Change** | Swaps in another element from the repository |
| **Create** | Creates a new element inside this step |
| **Edit** | Opens **Update Element** for name, screen name, type, and value |

### Replace what a step does

<Steps>

1. **Open the step** — Click the step you want to change.

2. **Describe the replacement** — Start typing to see matching NLPs, then select and configure one.

3. **Commit it** — Click **Update** to save, or **Dismiss** to restore the original.

</Steps>

### Step options

Hover a step and click the ellipsis icon on its right.

| Option | What it does |
| --- | --- |
| **Execute from Here** | Starts execution at this step and skips every earlier one |
| **Disable Step** | Keeps the step but skips it during execution |
| **Ignore Step Result** | Leaves the step's pass or fail out of the overall result |
| **Enable Visual Testing** | Captures and compares screenshots for this step |
| **Step Settings** | Opens **Step Details** for timeout, screenshots, and advanced options |
| **Clone Step** | Copies the step directly below itself |
| **Step Above**, **Step Below** | Inserts an empty step on that side and opens the inline editor |
| **Delete Step** | Removes the step permanently |

<Aside type="note">
**Execute from Here** skips the earlier steps, so the browser may not be in the state this step expects. Set the application up manually first.
</Aside>

## Reorder steps

<Steps>

1. **Grab a step** — Click the step you want to move. The cursor becomes a grab icon.

2. **Drop it** — Drag it to its new position. The target highlights as you go.

3. **Commit the order** — Click **Save Changes**, or **Discard** to revert.

</Steps>

<Aside type="note">
Drag-and-drop is disabled while recording, while executing, and while a step is open for editing.
</Aside>

## Act on several steps at once

<Steps>

1. **Select the first step** — Hover a step. A checkbox replaces its number. Click it, and the floating action bar appears.

2. **Select the rest** — Click more checkboxes, or click **Select All** in the action bar.

3. **Apply an action** — Click an icon in the action bar.

</Steps>

| Action | What it does |
| --- | --- |
| **Step Settings** | Applies shared settings, such as timeouts and screenshot behaviour, to every selected step |
| **Create Step Block** | Groups the selection into a reusable step block |
| **Create Step Group** | Combines the selection into a [step group](/suite/web/tests/step-groups/) |
| **Delete** | Removes every selected step permanently |

## Delete steps

Delete one step from its ellipsis menu: click **Delete Step**, then **Delete** in the **Delete step?** dialog.

To delete several, select them by checkbox, click the **Delete** icon in the floating action bar, then confirm.

<Aside type="note">
Deleting a step cannot be undone, whether you delete one or a selection.
</Aside>

## FAQs

**Test steps stop updating mid-session, and recording new ones does nothing.**

The agent is incompatible with Chrome 139. Delete the whole `.testsigma` folder and restart Testsigma Terminal. That pulls a fresh agent and restores the session features.

**The session will not start because a port is in use.**

Leftover processes from an earlier install are holding the ports. On macOS, click **Quit Session**, then end any **wrapper** or **atto** processes in Activity Monitor. On Windows, close Copilot and end **abd**, **WinTestAutomation**, **appium**, **ios**, **atto-browser-agent**, and **chromeDriver** in Task Manager. Then delete every subfolder inside both `.testsigma` and the Testsigma application-support folder, and reinstall Testsigma Terminal.

**I get an authentication error while installing the Terminal.**

This happens when you switch accounts partway through an install, or when files from a previous install survive. Run the same cleanup as the port error above.

**Copilot launched the browser but the run never starts.**

Check the Terminal dashboard for your application type. A red dot means the component is still updating or has errored, and Copilot cannot launch until it turns green. **Logs** on the Terminal home screen explains a failed launch.

**Can I reuse a launch configuration across sessions?**

Yes. Click **Save configuration** in the launch panel and give it a name. Loading it later offers **Update configuration** so you can revise it in place.

**Where does a Copilot session's result go?**

Each session produces a dry-run result rather than a test plan result, so it does not affect your run history or reports.
