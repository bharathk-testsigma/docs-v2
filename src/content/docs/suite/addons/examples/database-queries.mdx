Testsigma publishes an add-on per database engine, each contributing NLPs that run queries as ordinary test steps. That lets a test seed data, read a value back, and assert on it without leaving the test case. All four install the same way.

<Prerequisites>

- The database is reachable from Testsigma, with the tables your test needs.
- You know how to [install a community add-on](/suite/addons/marketplace/).

</Prerequisites>

## Install the add-on

<Steps>

1. **Open the marketplace** — Go to **Addons → Add-ons**.

2. **Find the add-on** — Under **New & Updated Addons**, search for the one you need.

3. **Install it** — Click **Install**, then refresh the page.

</Steps>

| Database | Add-on |
| --- | --- |
| MySQL | `mysql_queries` |
| Oracle | `OracleDB_Queries` |
| MongoDB | `MongoDB_NLPs` |
| PostgreSQL | `PostgreSQL_Queries` |

Its NLPs appear in step suggestions once installed. Start typing the query wording in a test step and select the one you want.

<Aside type="note">
Every connection URL below carries a username and password in plain text, and it is stored on the test step. Use a dedicated test-database account with the narrowest rights that work, never a production credential.
</Aside>

## MySQL

The connection URL follows one pattern throughout:

```
jdbc:mysql://<hostname>:<port>/<database_name>?user=<username>&password=<password>
```

For example, `jdbc:mysql://localhost:3306/customer_db?user=root&password=root`.

The add-on contributes ten NLPs, covering statements, stored procedures, script files, and cross-database comparison.

| NLP | What it does |
| --- | --- |
| Execute MySQL Query on the Connection `DB_Connection_URL` | Runs any statement |
| Execute MySQL Query … and verify affected rows count is `Row-Count` | Runs a statement and asserts how many rows it touched |
| Execute MySQL Select-Query … and store output into a `variable-name` | Runs a `SELECT` and keeps the result in a runtime variable |
| Execute MySQL Select-Query … and verify output is `Expected_Value` | Runs a `SELECT` and asserts the result |
| Execute MySQL Update Query on the Connection `DB_Connection_URL` | Runs an `UPDATE` |
| Execute MySQL Create Procedure Query on the Connection `DB_Connection_URL` | Creates a stored procedure |
| Call MySQL Stored Procedure Query on the Connection `DB_Connection_URL` | Calls one, for example `CALL GetCustomerDetails(1)` |
| Execute MySQLScriptFile `filepath` on the Connection `DB_Connection_URL` | Runs a `.sql` file |
| Validate MySQL `Query1` and compare with the Query `Query2` from the Connection … | Compares two queries against one database |
| Validate MySQL Query on the Connection `DB_Connection_URL1` and compare with the data from the Connection `DB_Connection_URL2` | Compares one query across two databases |

Storing and asserting a value takes two steps. Store first:

```sql
SELECT name FROM employees WHERE id = 2
```

Then reference the variable with `$` in the verify step's **Expected_Value**, such as `$Test` for a variable named `Test`.

A script file runs whatever it contains, which is the usual way to set up a fixture:

```sql
CREATE TABLE IF NOT EXISTS employees (
      id INT PRIMARY KEY,
      name VARCHAR(100),
      email VARCHAR(100)
);
INSERT INTO employees (id, name, email)
VALUES (1, 'John Doe', 'john.doe@example.com'),
      (2, 'Jane Smith', 'jane.smith@example.com');
SELECT * FROM employees;
```

## Oracle

Use the **Execute OracleDB Query on the Connection `DB_Connection_URL` and verify affected rows count is `Row-Count`** NLP.

<Steps>

1. **Enter the query** — Click the **Query** placeholder and type the SQL, such as `SELECT * FROM employees WHERE employee_id = 103;`.

2. **Enter the URL** — Click the **DB_Connection_URL** placeholder and build it from the syntax below.

3. **Set the expected rows** — Click the **Row-Count** placeholder and give the number of affected rows to assert.

4. **Save** — Click **Create Step**.

</Steps>

```
jdbc:oracle:thin:@//<host>:<port>/<service_name>?user=<username>&password=<password>&internal_logon=<role>
```

| Placeholder | What it takes |
| --- | --- |
| Host | The database server hostname, such as `localhost` |
| Port | The port the database listens on, such as `1521` |
| Service Name | The service name, or the SID if no service name exists |
| Username | The database user, such as `SYS` |
| Password | That user's password |
| Role | The database role, such as `SYSDBA` |

Two worked examples, one per identifier style:

```
jdbc:oracle:thin:@//localhost:1521/FREE?user=SYS&password=Test@123&internal_logon=SYSDBA
jdbc:oracle:thin:@//testing-email.com:1521/TFCP?user=test_fcp_develop&password=sigma&internal_logon=default
```

<Aside type="note">
For the service portion: choosing **SID** means entering `FREE`, the default service. Choosing **Service Name** means entering your actual service name.
</Aside>

## MongoDB

Install `MongoDB_NLPs`. Its NLPs take these parameters.

| Parameter | What it is | Example |
| --- | --- | --- |
| `DBname` | The database holding the collections | `e-commerce`, `blog`, `social-media` |
| `CollectionName` | A group of MongoDB documents | `users`, `products`, `orders` |
| `MongoDB_Connection` | The connection to a server or cluster | `MongoClient`, `Mongoose` |
| `MongoDB_ConnectionURL` | The address of the server or cluster, with connection options | `mongodb://localhost:27017/blog` |

## PostgreSQL

Install `PostgreSQL_Queries`. Its NLPs take these parameters.

| Parameter | What it is | Example |
| --- | --- | --- |
| `Query` | A query to execute | `SELECT * FROM table_name;` |
| `Row_Count` | The number of rows in a result set | `SELECT COUNT(*) FROM table_name;` |
| `DB_ConnectionURL` | The connection URL | `postgresql://user:password@localhost:5432/database_name` |
| `PG_DBConnectionURL` | The same, by host and port | `postgresql://username:password@host:port/database_name` |
| `Variable-Name` | A variable to assign a value to | `var_name` |
| `Select-Query` | A `SELECT` returning a result set | `SELECT column_name FROM table_name WHERE condition;` |
| `Expected-Value` | A value to compare the result against | The value you expect back |
