A post-plan hook is an add-on that runs once a test plan execution completes, whether it passed or failed. You write the action, publish it, then attach it in the plan's settings. Emailing a run summary is the usual first one.

<Prerequisites>

- You know what an [add-on](/suite/addons/) is and can build one — see [Build your own add-on](/suite/addons/build/).
- A test plan exists that you can attach the hook to.

</Prerequisites>

## Write the hook

Unzip the downloaded template and open the folder in your IDE as a Java project, with Maven as the build tool. It is a Maven project with a `pom.xml` and an example post-plan hook under the `com.testsigma.addons.hooks` package.

The template's example sends the execution run result to three configured email addresses, which is a working starting point for most notification hooks.

<Aside type="note">
A `TestData` reference must be wrapped in curly brackets to be recognised as a post-plan hook field. Without the brackets the field never appears in the plan's settings, and the hook looks like it has no inputs.
</Aside>

<Aside type="note">
One hook per add-on. If you need two post-plan behaviours, that is two add-ons.
</Aside>

## Test the code

Verify the hook before uploading it. Use JUnit or TestNG as the runner: right-click the test class, run it, and confirm the behaviour is what you intended.

## Upload it

<Steps>

1. **Zip the project** — Save your changes, then zip the project folder with `zip -r addonName.zip . -x "*"`.

2. **Upload the code** — Go to the add-ons page, open your add-on's dropdown, and click **Upload Code**.

3. **Confirm** — Select the ZIP and apply it.

</Steps>

The same dropdown also offers **Manage Tags** for categorisation labels, **Edit Description**, and **Delete**.

## Publish it

Click **Publish** in the add-on's dropdown, which appears once code is uploaded. Choose **Public** to give it to the Testsigma community, or **Private** to keep it inside your organisation, then confirm.

An automatic security check runs. Passing it publishes the add-on, and failing it sends you an email.

<Aside type="note">
Trial accounts go through Testsigma's review as well as the automated check. An email confirms approval, so build in time for it.
</Aside>

## Attach it to a test plan

<Steps>

1. **Open a plan** — Create a test plan or open an existing one, with a test suite and test machine added.

2. **Open the settings** — Go to the **Test Plan Settings** tab.

3. **Reveal the hooks** — Click the right arrow before **Hooks**.

4. **Select and configure** — Choose your add-on and fill in its custom fields.

</Steps>

The hook's result appears with the run: the plan-level run overview reports the post plan hook outcome along with its add-on details.
