Text rendered inside an image is invisible to a locator. An OCR add-on reads it anyway, by implementing the SDK's OCR interface and exposing three extraction methods to your test steps. This page covers what to change in the template.

<Prerequisites>

- You have generated an add-on template and can build it — see [Build your own add-on](/suite/addons/build/).
- The project opens in your IDE as a Java module, imported as Maven or Gradle.

</Prerequisites>

## Prepare the project

<Steps>

1. **Unzip it** — Open the extracted folder in your IDE as a Java module.

2. **Import the build** — Import the module as Maven or Gradle.

3. **Find the two things you edit** — `pom.xml` holds the dependencies, and `src` holds the sample Java files with the add-on's functions.

</Steps>

## Implement the OCR methods

Add the OCR dependencies your implementation needs to `pom.xml` first. Then set up a class implementing the OCR interface and fill in three methods.

| Method | What it extracts |
| --- | --- |
| `extractTextFromPage()` | Text from an entire page |
| `extractTextFromImage(OCRImage image)` | Text from a given `OCRImage` object |
| `extractTextFromElement(Element element)` | Text from a given `Element` object |

<Aside type="note">
All three return a `List` of `OCRTextPoint` objects. Each point carries where the text sits within its source, so you can act on position and not only on the string.
</Aside>

## Use it in a test case

Publish the add-on, and its NLPs become available in the application like any other add-on action. Start typing the action's wording in a test step and select it from the suggestions.
