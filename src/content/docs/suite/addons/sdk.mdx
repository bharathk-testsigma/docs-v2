The Testsigma SDK lets add-on code reach back into the run around it. Two classes carry most of that. `RunTimeData` reads and writes runtime variables, and `RunMetaData` reports facts about the execution itself.

## Get the dependency

An add-on template already depends on the current SDK. A project generated from Suite needs nothing added.

For a project you assemble yourself, take the Maven dependency from the [testsigma-java-sdk repository](https://github.com/testsigmahq/testsigma-java-sdk#testsigma-sdk-dependency). You can also generate the project from the [add-on archetype](https://github.com/Testsigmahq/testsigma-addon-archetype#testsigma-maven-archetype-for-creating-add-on-project).

## Runtime data

Runtime variables are how one step hands a value to a later step. To reach them, declare a `RunTimeData` field and annotate it.

```java
@RunTimeData
private com.testsigma.sdk.RunTimeData runTimeData;
```

The class exposes getters and setters for a key and a value. Setting a runtime property is three lines.

```java
runTimeData = new com.testsigma.sdk.RunTimeData();
runTimeData.setKey("tokenKey");
runTimeData.setValue("token_value");
```

### A complete action

This add-on reads the text of a PDF the browser is displaying. It stores that text in a runtime variable, named from the step's test data.

```java
package com.testsigma.add-ons.pdf.web;

@Data
@Action(actionText = "Read the content from pdf and store the text into a runtime-variable variable",
       description = "Extracts the text from the PDF and stores the extracted text into a run time variable",
       applicationType = ApplicationType.WEB)
public class ReadpdfContent extends WebAction {
   @TestData(reference = "variable")
   private com.testsigma.sdk.TestData testData;

   @RunTimeData
   private com.testsigma.sdk.RunTimeData runTimeData;

   @Override
   public Result execute() {
       Result result = Result.SUCCESS;
       logger.info("Initiating execution");
       logger.debug("test-data: " + this.testData.getValue());
       URL url;
       BufferedInputStream fileParse;
       if (driver.getCurrentUrl().contains(".pdf")) {
           setSuccessMessage("pdf file detected");
       } else {
           setErrorMessage("Not a pdf file");
           return Result.FAILED;
       }
       try {
           url = new URL(driver.getCurrentUrl());
           InputStream is = url.openStream();
           fileParse = new BufferedInputStream(is);
           PDDocument doc = null;
           doc = PDDocument.load(fileParse);
           String st = new PDFTextStripper().getText(doc);
           runTimeData = new com.testsigma.sdk.RunTimeData();
           runTimeData.setKey(testData.getValue().toString());
           runTimeData.setValue(st.trim());
           setSuccessMessage("The Stored content in PDF is : " + st.trim()
               + "and stored in the runtime variable :" + testData.getValue());
       } catch (IOException e) {
           e.printStackTrace();
           setErrorMessage("Cause of Exception:" + e.getCause().toString());
           return Result.FAILED;
       }
       return result;
   }
}
```

## Run metadata

Sometimes an action needs to know about the execution it belongs to, not just the page in front of it. `RunMetaData` carries that.

An instance called `runMetaData` is already in the template, for every add-on NLP. You do not create one, and you can reach it anywhere in the add-on. It is populated for dry test case executions and test plan executions alike.

| Method | What it returns |
| --- | --- |
| `getTestDataId()` | The test data profile ID available to the executing step, as a `long` |
| `getRunId()` | The dry test case result ID for a dry execution, or the test plan result ID for a plan execution, as a `long` |
| `getIsAdHocRun()` | `true` for a dry test case execution, `false` for a test plan execution |
| `getTriggeredType()` | How the execution was triggered, as an enum: `MANUAL`, `SCHEDULED`, or `API` |
| `getTriggeredByEmail()` | The email of the user who started the execution, as a `String` |
| `getStartTime()` | When the execution started, as a `String` |

### Reading it

```java
package com.kasyap.testsigma.addons.web;

import.com.testsigma.sdk.Result;

@Action(actionText = "Verifying RunMetadata", applicationType = ApplicationType.WEB)
public class CustomNLP extends WebAction {
@Override
    protected Result execute() throws NoSuchElementException {
        logger.info("Triggered By : " + runMetaData.getTriggeredByEmail());
        logger.info("TestDataProfile ID available to step" + runMetaData.getTestDataId());
        logger.info("Execution Result ID: " + runMetaData.getRunId());
        logger.info("Is Dry Execution? : " + runMetaData.getIsAdHocRun());
        logger.info("TriggeredType (Manual/Scheduled/API) ? " + runMetaData.getTriggerType());
        logger.info("Execution Started at (UTC format) : " + runMetaData.getStartTime());
        return Result.SUCCESS;
    }
}
```

<Aside type="note">
`getStartTime()` returns UTC. Compare it against a local timestamp without converting, and the add-on's time arithmetic comes out hours wrong.
</Aside>
