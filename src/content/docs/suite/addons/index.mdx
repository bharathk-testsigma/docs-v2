## Why addons exist

End-to-end testing covers a large, varied set of features. Some of them are unique to your application under test. Predicting an action statement for every one is not feasible, so Suite makes the action list extensible instead.

Take `scroll indefinitely till the bottom of the page`. It suits an application that appends items as you scroll, the way Pinterest does. If your test has to reach the footer to verify a copyright notice, an addon automates it at scale.

## What you can build

| Type | What it does |
| --- | --- |
| Custom action | Automates an action Suite's built-in set does not cover |
| Test data generator | Produces test data the [default generators](/suite/web/test-data/data-generators/) do not |
| Conditional if | Runs a sequence of steps when your own condition matches |
| While loop | Repeats a sequence of steps until your own condition matches |
| Post-plan hook | Runs after a test plan finishes, whatever the result |

Testsigma publishes step-by-step tutorials for each type: [custom actions](https://testsigma.com/tutorials/addons/how-create-addons-actions/), [data generators](https://testsigma.com/tutorials/addons/how-create-addons-test-data-generators/), [conditional if](https://testsigma.com/tutorials/addons/how-create-addons-conditional-if/), and [while loops](https://testsigma.com/tutorials/addons/how-create-addons-while-loops/).

## Public, private, or borrowed

You have three routes to an addon, and they are not exclusive.

Install one from **Community**, which holds addons published by other teams and by Testsigma. Write your own and publish it publicly, sharing it with the wider community. Or keep it private to your organisation. Private is the right choice when the code is specific to your applications, or carries anything proprietary.
