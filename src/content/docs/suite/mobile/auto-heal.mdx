Broken locators are the usual reason a healthy mobile suite decays. Auto-Healing detects that your app changed, compares the current screen against the stored locators, and corrects invalid ones during the run. It reports every change, so healing stays visible.

<Prerequisites>

- You are an administrator, or someone who can change project preferences.

</Prerequisites>

## Turn on Auto-Healing

<Steps>

1. **Open preferences** — Go to **Settings → Preferences**.

2. **Enable it** — Turn on the toggle on the **Auto Healing** widget.

</Steps>

Runs from that point on correct locators without anyone intervening.

<Aside type="note">
Auto-Healing works on its own, and the generative AI feature makes it broader: deeper locator analysis and better coverage. If your account has no access to it, Testsigma support can enable it.
</Aside>

## What Auto-Healing corrects

During an Android, iOS, or mobile web run, a locator that no longer matches is replaced with one that does, and the step carries on. A stale shorthand like `emai` heals into a real locator such as `//android.widget.EditText[@resource-id="email"]`.

Unified projects add Gen AI Auto Heal. When an [element](/suite/mobile/elements/) recorded on Android fails on iOS, the other platform's screenshot provides the healing context, so the dual-locator pair stays usable on both platforms.

Auto-Healing fixes how an element is *found*. It does not fix a step whose logic is wrong, and it does not invent an element that no longer exists in the app.

## Review Auto-Heal insights

A healed run tells you what it did. An auto-heal badge beside the test case name in **Run Results** reports how many steps were healed.

<Steps>

1. **Open the step** — Click the test step where the element was healed.

2. **Open the detail** — In **Step Result**, click **Auto-Heal Details**.

3. **Read the insight** — The overlay shows which element was healed and how its locator changed.

</Steps>

## Make a healed locator permanent

A heal applies to that run. The stored element keeps its old locator until you promote the new one, so every subsequent run heals again.

<Steps>

1. **Open the insight** — From **Auto-Heal Details**, click **Update**.

2. **Confirm** — In the **Update Element** dialog, click **Update** again.

</Steps>

<Aside type="note">
Promoting a healed locator rewrites the element for every test case that uses it. Check the insight first: healing onto the wrong element is silent, and the test still passes.
</Aside>
