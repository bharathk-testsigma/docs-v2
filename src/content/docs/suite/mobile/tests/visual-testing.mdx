Visual testing compares how an app screen looks against a stored baseline image, using the per-step screenshots the run captures on the device. It is off by default, and you turn it on per step, keeping the comparison to screens where appearance matters.

<Prerequisites>

- You have a test case with steps that reach the screens you want compared.
- You know which steps are worth comparing. Every enabled step stores an image.

</Prerequisites>

## Enable it on one step

<Steps>

1. **Open the step options** — Click the ellipsis icon on the test step.

2. **Turn it on** — Select **Enable Visual Testing**.

3. **Save** — Click **Update Step**.

</Steps>

## Enable it on several steps

<Steps>

1. **Select the steps** — Tick the checkbox beside each step you want compared.

2. **Open bulk settings** — Click **Update Settings** in the menu bar.

3. **Apply** — In the **Bulk Update Settings** overlay, tick **Enable Visual Testing** and click **Update**.

</Steps>

<Aside type="note">
Nothing is compared on the first run. Testsigma needs a baseline image for each enabled step, so visual testing starts reporting from the next successful run onward. Compare like with like: a baseline captured on one device and resolution only makes sense against runs on the same device and resolution.
</Aside>

## Review the differences

Run the test case, then open the result. Each enabled step carries a camera icon: green means the current image matches the baseline, red means it does not.

Click the camera icon to open the **Visual Difference** overlay. It carries five controls.

| Control | What it does |
| --- | --- |
| **Highlight Differences** | Marks what changed, which is faster than comparing two images by eye |
| **Hide Visual Differences** | Conceals the markers again |
| **Select region to ignore from visual comparison** | Excludes an area from the comparison |
| **Merge base image and current image** | Overlays the two so you can see the shift |
| **Zoom in** and **Zoom out** | Inspect a detail closely |

**AI Insights** produces a UI Difference Analysis Report whenever differences are found. It names the likely cause of the mismatch and suggests a resolution.

## Tune the comparison

A pixel-exact comparison flags things you do not care about — a clock in the status bar is enough. Two settings fix that.

**Comparison mode.** **Strict** requires an exact pixel match. **Lenient** compares against a threshold: at 70%, the step passes when 70% of pixels match. Set it from the camera icon overlay under **Visual Testing Mode**.

**Ignore regions.** Draw regions to exclude dynamic content — the status bar, timestamps, user-specific data. Select **Select region to ignore from visual comparison**, mark the areas, and click **Save ignore region**.

By default a visual difference is reported but does not fail the test case. **Test Case Settings → Fail Test Case if Visual Testing Fails** changes that; turn it on only once baselines and ignore regions are settled.

## Accept a new baseline

When an app redesign is intentional, the baseline is now wrong and every run will keep failing against it.

<Steps>

1. **Open the difference** — Click the camera icon on the step.

2. **Promote the current image** — At the top right, tick **Mark as base image** for the **Current Image**.

</Steps>

<Aside type="note">
Promoting a baseline is how a real regression gets accepted permanently. Confirm the change was intended before you tick it.
</Aside>

## Compare against a Figma design

Instead of comparing a run to a previous run, you can compare it to the design it was built from. The baseline becomes a Figma frame.

<Steps>

1. **Enable visual testing** — Click the kebab menu on the step, select **Enable Visual Testing**, then click **Update Step**.

2. **Open the Figma view** — Hover the step and click the camera icon to open **Visual Difference – Figma**.

3. **Add the design** — Under **Base Line Image**, click **Add Figma Designs**.

4. **Set the target device** — In **Add Devices**, select the mobile device to compare at — a device, not a browser, for Android and iOS.

5. **Link the frame** — Enter the Figma frame link in **Frame Link**, click **Refresh** to verify it, then click **Save**.

6. **Run and review** — Execute the test case, click the camera icon on the step result, and open the **Visual Difference – Figma** tab.

</Steps>

<Aside type="note">
The Figma frame dimensions must match the device resolution, and the device set here must match what you pick on the **Ad-Hoc Run**, or the comparison is meaningless.
</Aside>
