Mobile test cases are built four ways: typed as NLP steps, recorded from a mobile web site, recorded from a native app through Copilot's mirrored session, or generated by Atto. A Unified project runs one test case on both Android and iOS.

<Prerequisites>

- The application exists in your project, and for native apps the build (APK or IPA) is uploaded as an **App Source**.
- For Copilot routes, [Testsigma Terminal](/suite/installation/testsigma-terminal/) is installed and a device is connected as a test machine.
- For mobile web recording, the Testsigma Chrome extension is installed.

</Prerequisites>

<Aside type="note">
Unified Mobile runs on the Modern stack only. Elements carry separate Android and iOS locators, NLPs show a platform badge, and steps that do not apply to the running platform report **Not executed** rather than failing.
</Aside>

## Create tests manually using NLPs

The typed route is the same as [web authoring](/suite/web/tests/author-tests/#create-tests-manually-using-nlps): create the test case, type an action, and pick the NLP. Mobile adds gesture NLPs — tap, swipe, pinch — and device NLPs alongside the shared set.

## Record a mobile web test

<Steps>

1. **Start recording** — On the **Test Case Details** page, click **Record**. A new window opens; enter the URL.

2. **Open the recorder panel** — Press <kbd>F12</kbd>, dock DevTools to the right, select **Companion Mode** in the action bar, then choose **Testsigma Recorder** from the `>>` overflow menu.

3. **Pick the device dimension** — Select a device from the **Dimensions** dropdown. If yours is missing, choose **Edit → Add custom device**; screen-specific behaviour only shows up at the right dimensions.

4. **Perform the flow** — Interact with the page. Each action becomes a step.

5. **Stop** — Click **Stop** and review the captured steps.

</Steps>

## Record a native app test with Copilot

<Steps>

1. **Create the test case** — In **Create Tests → Test Cases**, add a test case under its feature and scenario.

2. **Launch Copilot** — Click **Create Step**, then **Copilot**. Configure the **Test Machine** and **App Source** and click **Launch**. Copilot opens a mirrored session of the app inside Suite.

3. **Record** — Click **Rec** and drive the app. Every tap and input is captured as a step.

4. **Finish** — Click **Stop Recording**, then **Exit Copilot → Stop Copilot**. The steps land on the **Test Case Details** page.

</Steps>

## Generate test cases with Atto

Atto turns a prompt or a requirement into mobile test cases the same way it does for web — see [Learn & Execute](/suite/atto/learn-and-execute/). Atto generation is not yet available for Unified projects.

## FAQs

**Where do I find an Android app's package and activity name?**

The package (`com.example.myapp`) locates the app; the activity is its "page". With the app open on a connected device, run `adb devices`, then `adb shell dumpsys window | grep -E 'mCurrentFocus'` (`| find "mCurrentFocus"` on Windows). The output shows both — for WhatsApp, `com.whatsapp` and `com.whatsapp.HomeActivity`.

**Where do I find an iOS app's bundle ID?**

Three ways. App Store: take the number from the app's iTunes URL and open `https://itunes.apple.com/lookup?id=<number>`, then search the output for `bundleId`. Local IPA: rename to `.zip`, unzip, and read `softwareVersionBundleId` in `iTunesMetadata.plist`. Only on the phone: browse the device with a tool like iExplorer and read the same plist.

**Tap and type are slow on React Native or Flutter apps.**

Add the `appium:waitForIdleTimeout` desired capability (String, `1000L`) to the run or recording. It stops Appium waiting for the app to report idle between actions.

**A tap fails with "Element is either hidden or disabled".**

Tap checks three things: the element is enabled, visible, and the locator is right. If it sits below the fold, Suite scrolls internally to find it — but confirm the first two with Appium Inspector (`enabled` and `visible` must both be `true`).

**Scroll to Element does nothing in a native app.**

That NLP only works when the target is already rendered in the viewport. Swipe first: *Swipe from middle to top on the screen* (or bottom-to-top for a longer jump, top-to-bottom to go back). If you do not know how many swipes are needed, put the swipe inside a *While* loop.

**The mobile test recorder fails to start.**

Check the recorder logs for the real reason. The two usual ones: the manifest's default activity is not the activity that actually launches first (start manually with the real activity and package name, and have the developers fix the manifest), and vendor-customised Android builds — Xiaomi, Vivo, Huawei — needing extra developer-option settings before they connect cleanly.

**Google Play Protect blocks the SMS Forwarder install.**

Temporarily pause it: **Play Store → profile → Play Protect → settings → Scan apps with Play Protect** off, install, then turn it back on.
