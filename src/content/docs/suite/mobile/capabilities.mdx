Desired capabilities tune the device a mobile run uses: granting app permissions at install, keeping app data between sessions, or approving iOS pop-ups. They apply per run or per machine profile, never to the test case itself.

## Capability format

Every capability is three fields.

| Field | What it holds |
| --- | --- |
| **Key** | The property name, such as `autoGrantPermissions` |
| **Data Type** | The type of the value: boolean, String, or Integer |
| **Value** | The value itself |

## Add capabilities to a run

On the **Test Case Details** page click **Run**, then expand **Desired Capabilities** on the **Ad-Hoc Run** overlay and add your rows. **Delete** removes one.

For a plan, capabilities belong to the device profile rather than the run. Open the test plan, go to **Add Test Suites & Link Machine Profiles**, click **Test machine settings** on the profile you want, then expand **Desired Capabilities**.

The difference catches people out: a capability on an ad-hoc run applies once, while a capability on a device profile applies to every run of every plan that uses that profile.

## Android capabilities

| To do this | Key | Data Type | Value |
| --- | --- | --- | --- |
| Keep app data between hybrid sessions on a local device | `noReset` | boolean | `true` |
| Grant the app's manifest permissions at install | `autoGrantPermissions` | boolean | `true` |
| Speed up a React Native or Flutter app | `appium:waitForIdleTimeout` | Integer | A shorter wait, in milliseconds |

## iOS capabilities

| To do this | Key | Data Type | Value |
| --- | --- | --- | --- |
| Approve every permission pop-up, including location, contacts, and photos | `autoAcceptAlerts` | boolean | `true` |
| Dismiss every permission pop-up instead | `autoDismissAlerts` | boolean | `true` |
| Stop Testsigma re-signing the app | `resignApp` | boolean | `false` |

By default an iOS app is re-signed with the provisioning profile you uploaded, so it can install on the device during execution. Passing `resignApp=false` prevents that.

<Aside type="note">
Re-signing deletes the entitlements in your iOS app. If the app is already signed through the Apple Developer Enterprise Program, turn re-signing off rather than losing them.
</Aside>

Testsigma's UI describes this setting as "ResignEnabled"; the capability key you pass is `resignApp`.

## Biometric authentication

Simulating a biometric event lets you test how the app recognises and responds to one, on both Android and iOS.

| Name | Data Type | Value |
| --- | --- | --- |
| `testsigma.allowTouchIdEnroll` | Boolean | `True` |

<Steps>

1. **Open the run panel** — Click **Run** on the **Test Case Details** page.

2. **Open the capabilities** — On the **Ad-Hoc Run** overlay, click **Desired Capabilities**.

3. **Add it** — Enter `testsigma.allowTouchIdEnroll` as the **Key**, select **Boolean**, and set the **Value** to `True`.

4. **Run it** — Click **Run Now**.

</Steps>

<Aside type="note">
This one works in Testsigma Lab only. It is not supported in local execution, so a device attached to your own agent ignores it.
</Aside>

## Google Play Store credentials

Testing an in-app purchase flow, a Google Pay payment, or the production build from the store all need a real Play Store login. Pass your own credentials rather than relying on the device's.

| Name | Data Type | Value |
| --- | --- | --- |
| `browserstack.appStoreConfiguration` | String | `{"username": "play-store-email", "password": "play-store-password"}` |

<Aside type="note">
This capability puts a real password into a run configuration. Use a dedicated test account, never a personal or production Play Store login. Remember that a machine profile keeps the value for every run using it.
</Aside>

## Inspect Android WebViews

WebView elements are only inspectable if the app enables WebView debugging. That is an app-side change rather than a capability: call the static method on the WebView class.

```java
WebView.setWebContentsDebuggingEnabled(true);
```

The setting applies to every Android WebView in the app.

WebView debugging is independent of the `debuggable` flag in the app manifest. To tie it to debug builds only, set `WebView.setWebContentsDebuggingEnabled(BuildConfig.DEBUG)` instead.

## Allow screenshots of a secured screen

Screenshots are permitted by default on Android and iOS. A blank screenshot in a result usually means the developer blocked capture on that screen.

On Android, remove this flag from `MainActivity.java`, or from whichever activity you need to inspect:

```java
getWindow().setFlags(WindowManager.LayoutParams.FLAG_SECURE,
        WindowManager.LayoutParams.FLAG_SECURE);
```

On iOS, a third-party tool is usually the thing blocking capture. Remove that restriction so Testsigma can inspect the screen.
