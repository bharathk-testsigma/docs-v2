An app manager deploys Testsigma Agent and Testsigma Terminal to managed Windows devices at scale. Testsigma supports enterprise rollouts through PatchMyPC, which packages each installer and publishes it to Microsoft Intune for automatic delivery to managed devices.

## How the apps are supported

For a manual, single-device install, see [Testsigma Agent](/suite/get-started/installation/testsigma-agent/) or [Testsigma Terminal](/suite/get-started/installation/testsigma-terminal/) instead.

Testsigma Agent and Testsigma Terminal are not in PatchMyPC's built-in catalog, so PatchMyPC onboards them as **Custom Apps**. PatchMyPC packages the installer and publishes it to Intune as a Win32 app, and Intune delivers it to managed devices.

<Aside type="note">
PatchMyPC deployment covers Windows `.exe` installers only. macOS `.dmg`, Linux, and the agent's raw ZIP are not supported through it.
</Aside>

Testsigma provides the installer for each build. Your IT team owns everything in PatchMyPC: adding the custom app, setting the install command and detection rule, and publishing to Intune.

Before you begin, confirm that PatchMyPC Publisher is installed and connected to your Intune tenant. Testsigma must also have provided the current Windows `.exe` installer for each app you deploy. You need access to **Local Content > Custom Apps** in the Publisher.

A custom app installer must meet three conditions:

- **Silent install**: it installs with no UI or user interaction.
- **Matching install context**: a machine-wide install deploys in Intune SYSTEM context, and a per-user install deploys in Intune user context.
- **Stable detection**: a reliable way to confirm whether a version is installed, using a file path that does not change between builds.

Custom apps get no catalog-style URL monitoring and no automatic version detection. Each new version needs a manual **Add Version** upload.

## Deploy Testsigma Agent

Testsigma Agent installs per user (HKCU and the user profile), so deploy it in Intune **user context**, not SYSTEM context.

<Steps>

1. **Add the app**: in the PatchMyPC Publisher, go to **Local Content > Custom Apps** and click **Add**.

2. **Enter the metadata**: set **Name** to **TestsigmaAgent**, **Vendor** to **Testsigma**, **Version** to the value of **agent.version** in **agent.properties**, and **Architecture** to x64. Type the name exactly. A typo breaks the auto-generated DisplayName detection.

3. **Upload the installer**: upload **TestsigmaAgent-Windows.exe**.

4. **Enter the install command**: use the commands below.

5. **Confirm the detection rule**: PatchMyPC's auto-generated detection works for Testsigma Agent without changes.

6. **Publish**: publish the app to Intune, then create the assignment groups on the Intune side.

7. **Verify on one device**: deploy to a single managed test device and confirm the install before rolling out broadly.

</Steps>

```text
Install:   TestsigmaAgent-Windows.exe /S
Uninstall: <install-dir>\Uninstall.exe /S
```

## Deploy Testsigma Terminal

Testsigma Terminal supports a machine-wide or a per-user install at runtime. The install switch decides which.

<Steps>

1. **Add the app**: in the PatchMyPC Publisher, go to **Local Content > Custom Apps** and click **Add**.

2. **Enter the metadata**: set **Name** to **TestsigmaTerminal**, **Vendor** to **Testsigma**, **Version** to the value in **package.json**, and **Architecture** to x64. Type the name exactly. A typo breaks the auto-generated DisplayName detection.

3. **Upload the installer**: upload **TestsigmaTerminal-Setup-\<version\>.exe**.

4. **Enter the install command**: use the command for the scope you want, from the block below.

5. **Confirm the detection rule**: PatchMyPC's auto-generated detection works for Testsigma Terminal without changes.

6. **Publish**: publish the app to Intune, then create the assignment groups on the Intune side.

7. **Verify on one device**: deploy to a single managed test device and confirm the install before rolling out broadly.

</Steps>

```text
System-level (all users):  TestsigmaTerminal-Setup-<version>.exe /S /allusers
User-level (current user): TestsigmaTerminal-Setup-<version>.exe /S /currentuser
Uninstall:                 "C:\Program Files\TestsigmaTerminalBlackpearl\Uninstall TestsigmaTerminalBlackpearl.exe" /S
```

<Aside type="note">
Match the install switch to the Intune deployment context. Use `/S /allusers` in SYSTEM context and `/S /currentuser` in user context. A mismatch installs the app where the assigned user cannot see it, and Intune reports the deployment as failed.
</Aside>

## Add a new version

Custom apps need a manual upload for each version. PatchMyPC monitors no URL and detects no new builds.

<Steps>

1. **Get the installer**: Testsigma builds it and provides it to your IT team. The version comes from **agent.version** in **client/src/main/resources/agent.properties** for the agent, and from **package.json** for Terminal.

2. **Upload it**: in the PatchMyPC portal, open the app, select **Add Version**, upload the new installer, set the **Version**, confirm the install command and detection rule, and select **Create**.

3. **Sync**: the update deploys on the next daily sync, or immediately if you select **Sync Now**. Assigned devices upgrade automatically.

</Steps>

On the device, Terminal's electron-builder NSIS installer handles the in-place upgrade through its stable appId, **com.testsigma.testsigmaterminal**. The agent's **.onInit** block silently uninstalls the previous version before installing the new one, and data in `%APPDATA%\Testsigma` survives the upgrade.

A weekly release cadence turns that upload into a weekly manual task unless you offload it:

- **Rely on each app's built-in auto-update (recommended)**: both apps self-update independently of PatchMyPC. Let PatchMyPC and Intune handle the initial install only, and re-upload just for major or breaking changes that need a fresh install baseline.
- **Automate the upload**: script **Add Version** against the PatchMyPC Cloud API as part of your release pipeline, if your plan includes it. Confirm the API exposes custom-app version creation before relying on it.

<Aside type="note">
Disabling an app's built-in auto-update makes PatchMyPC and Intune the only update path. Every new version then needs an upload, and skipping one leaves devices on the old version.
</Aside>

## Troubleshooting

### Deployment reports as failed, but the app appears installed

The install context does not match the Intune deployment context. Terminal's `/S /allusers` must run in SYSTEM context. Terminal's `/S /currentuser` and the agent's `/S` must run in user context.

### Reinstall fails with "specified path does not exist"

A stale uninstall key from a prior install points to a path that no longer exists. Remove the stale uninstall key, then retry the install.
