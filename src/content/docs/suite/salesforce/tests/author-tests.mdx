Salesforce testing leans on three platform-specific tools. Metadata auto-learns your org's components. Smart NLPs compress multi-step UI flows. Copilot authors tests live. A four-step test covers what raw UI automation needs dozens for.

<Prerequisites>

- The [connected app](/suite/salesforce/setup/connected-app/) exists and a [metadata connection](/suite/salesforce/setup/connections/) has synced.
- The Testsigma Chrome extension is installed.
- For Copilot, [Testsigma Terminal](/suite/installation/testsigma-terminal/) is running.

</Prerequisites>

## Create tests manually using smart NLPs

Create the test case under **Create Tests → Test Cases** and click **Add new step**. The Salesforce-specific NLPs are catalogued in [Salesforce NLPs](/suite/salesforce/tests/salesforce-nlps/); the shape of a typical flow:

<Steps>

1. **Log in** — *Login to Salesforce application using Salesforce Connection connection*. Choose a [user connection](/suite/salesforce/setup/connections/), or create one inline with **Add Connection**.

2. **Get where you are going** — *Switch to Application*, picking the app from the dropdown.

3. **Create data through the API** — *Create record in Salesforce Object Form using Salesforce Connection and store the record id in variable test data*. Pick the object and fill the generated form. The record ID lands in a variable — no UI clicking.

4. **Act on it in the UI** — *Open the edit Salesforce Object form where record id is Record ID*, using the stored variable.

</Steps>

## Record with Copilot

Click **Copilot** on the test case. In the **Debug & Record** overlay, confirm Copilot is live, select the **Salesforce Metadata connection**, and click **Launch**. A mirrored org session opens. Record actions as steps. Pause on failure, step backward and forward, and edit steps without a re-run. Captured elements go straight to the [repository](/suite/salesforce/elements/).

## FAQs

**Which parts of a flow should go through the API instead of the UI?**

Data setup. The record NLPs are faster and less brittle than driving the forms. That leaves the UI steps to test what actually needs the UI.
