Salesforce elements are not captured manually. Metadata sync learns them from the org, so test steps pick from a ready repository. Field elements arrive named `ObjectName_FieldName` — `Account_CreatedDate` is `CreatedDate` on `Account`. Screens take their object's name.

## Find auto-learned elements

In any test case, add a step and hover the element placeholder. Click **Select Element**. The **Elements** overlay lists the learned repository.

<Aside type="note">
Auto-learned elements cannot be edited. The org's metadata is their source of truth. Element names must stay unique.
</Aside>

## Capture an element in Copilot

For anything the sync did not learn:

<Steps>

1. **Launch** — In the test case, click **Copilot**. Confirm it is live in the **Debug & Record** overlay, select the metadata connection, and click **Launch**.

2. **Capture** — In the recorder, click the element placeholder in the NLP and select **Create Element**. Click the UI element. The details are captured automatically.

</Steps>

## Repair elements after a metadata refresh

A refresh after org changes flags every element, step, and test case the change broke. The repair flow lives on the [connections page](/suite/salesforce/setup/connections/#recover-from-a-metadata-refresh): filter the warned test cases, hover the highlighted step, **View/Edit element**.
