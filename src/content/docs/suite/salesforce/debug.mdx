Debugging a Salesforce failure is a move from symptom to cause. The result tells you which step stopped the run and what the org's screen looked like. Copilot then lets you pause on that step against the live org and change the test case without starting over.

<Prerequisites>

- A run has failed, and you can open its result.
- For the interactive part, **Testsigma Terminal** is running on your desktop.

</Prerequisites>

## Narrow down why it failed

Most failures come from a short list of causes. Reading the evidence in order tells you which one you have.

<Steps>

1. **Find the failing step** — Open the result. Suite marks the step that failed and stopped execution.

2. **Look at the evidence** — Check the screenshot taken at that moment, and the execution recording at that timestamp if one was captured.

3. **Compare against the element** — Open the step's element information. A locator that no longer matches looks different from an org that never loaded.

</Steps>

These are the usual causes, roughly in order of how often they turn up:

- A Salesforce release shifted the Lightning markup, so the locator no longer matches.
- The org's configuration changed — a removed field, a renamed object — and the metadata is stale.
- The [user connection](/suite/salesforce/setup/connections/) could not log in, or its session expired.
- The locator was never unique, and the run picked a different match.
- A real bug in the org's customisation.

<Aside type="tip">
A shifted Lightning locator often heals on its own — check the auto-heal badge on the result before touching the element. For org changes, refresh the metadata: it flags every impacted element, step, and test case. See [Recover from a metadata refresh](/suite/salesforce/setup/connections/#recover-from-a-metadata-refresh).
</Aside>

## Step through it with Copilot

Copilot pauses a run on the step you choose, against the live org. You can then fix the step and carry on without a fresh run.

Set a debug point on the failing step, then launch a session from the test case editor. When the run pauses, the toolbar drives it: **Resume**, **Pause**, **Step Over**, and **Rec** to record a fix in the org instead of typing it.

[Copilot Mode](/suite/atto/copilot/) covers the launch panel, debug points, and every toolbar control.

## Collect logs from a run

A failure the screenshot does not explain is usually visible in the logs the run captured. **Show Logs** on the **Run Results** page opens the **Logs** view. Salesforce tests run in a browser, so the browser's own records apply.

| Log | What it holds |
| --- | --- |
| Console | Browser console output, when a console capability was set |
| Network | Every request and response, downloadable as HAR |

**Download log file** in the top-right corner saves the log for offline analysis, and the network log comes out as HAR.
