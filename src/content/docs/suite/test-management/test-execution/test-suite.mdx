A test suite is a group of test cases that run together, and it is what a test plan links to. A static suite holds the cases you pick. A dynamic suite holds whatever currently matches a filter.

<Prerequisites>

- You have test cases to group.
- You know whether the membership should be fixed or filter-driven.

</Prerequisites>

## Create a static test suite

<Steps>

1. **Start the suite** — Go to **Test Suites** and click **Create Test Suite**.

2. **Name it** — Enter a **Name**. Turn on the **Description** toggle to explain its scope for the team.

3. **Set a prerequisite** — Under **Pre-Requisite**, name anything that must be in place first, such as data or an environment.

4. **Label it** — Assign a **Label** to make the suite easier to filter later.

5. **Pick the cases** — Click **Add/Remove Test Cases**, tick cases in **Available Test Case**, then click the **+** icon to move them to **Selected for Test Suite**.

6. **Confirm** — Click **Add to Suite**.

</Steps>

Testsigma shows the toast **Test Suite created successfully.**

## Order the test cases

Drag and drop cases in **Selected for Test Suite** to change their execution order. To drop one, select it there and click the **-** icon.

## Configure AfterTest Suite

AfterTest Suite runs clean-up work once the suite's cases are done. Turn on the toggle, then choose two behaviours.

| Setting | Options |
| --- | --- |
| When to execute | **Once After All Test Cases**, or **For Every Test Case** |
| If it fails | **Fail the test suite**, or **Show the test suite result** |

Then add the specific test cases you want to run in that phase.

<Aside type="note">
**For Every Test Case** runs the teardown after each case rather than once at the end. On a twenty-case suite that is twenty teardowns, which is right for resetting state between cases and wrong for a single final clean-up.
</Aside>

## Create a dynamic test suite

A dynamic suite has no fixed membership. It re-evaluates its filter, so a new test case that matches is included without anyone editing the suite.

<Steps>

1. **Start it** — Go to **Test Suites**, expand **Create Test Suite**, and click **Create Dynamic Test Suite**.

2. **Name it** — Enter a **Name** in **Basic Details**.

3. **Add the filter** — In **Filtered Testcases**, click **Add filters to select test cases**, then expand **Add Filters** and choose them. Matching cases are selected automatically.

4. **Order them** — Expand **Sort by** to arrange the results.

5. **Save the filter** — Expand **Save Filter**, select **As New**, name it, tick **Mark as Public** if the team needs it, and click **Save**.

</Steps>

**Reset** clears every applied filter.

<Aside type="note">
A dynamic suite's contents change as your test cases change. That is the feature, and it is also the risk: a case that starts matching the filter joins the next run without review.
</Aside>

## Manage the suite list

The **Test Suites** page supports sorting, filtering, and searching, and lists each suite's title, type, creation date, creator, and status. Type is where you tell a static suite from a dynamic one.
