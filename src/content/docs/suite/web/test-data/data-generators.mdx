A data generator produces a value when the step runs, rather than reading one you stored. That covers names, emails, dates, and numbers, and it also covers values only available mid-run, such as an OTP sitting in a mailbox.

<Prerequisites>

- You have a test case with a step that takes test data.
- For the mailbox functions, a mailbox is linked to your account.

</Prerequisites>

## Add a data generator to a step

<Steps>

1. **Add the placeholder** — Write a step with a test data placeholder.

2. **Pick the type** — Click the placeholder and select **! Data Generator** from the **Test Data Types** dropdown.

3. **Choose the source** — In the **Data Generators** overlay, set **Type** to **Default** for the built-in set.

4. **Narrow it down** — Select a **Function Type**, then a **Function** from the list that belongs to it.

5. **Supply the inputs** — Each function takes its own inputs, such as a length, a domain, or a timeout.

</Steps>

## Built-in function types

Functions are grouped by what they produce. The generator you want is almost always in one of these.

| Function type | Produces |
| --- | --- |
| Name, NameFunctions | Person names and name parts |
| EmailFunctions | Usernames, random emails, and emails on a given domain |
| MailBoxFunctions | Values read out of a real inbox: OTPs, links, subjects, content |
| MailBoxAliasFunctions | A unique mailbox per run, plus the same read operations |
| PhoneFunctions, PhoneNumberFunctions | Phone numbers |
| Address, Company, Friends | Realistic addresses, company names, and related fields |
| DateFunctions | Dates, relative and absolute |
| Number, NumberFunctions, IdNumber | Numeric values and identifiers |
| StringFunctions, RandomString, RandomText | Strings and free text |
| Internet, DomainFunctions | URLs, domains, and internet artefacts |
| File | File-based values |
| ChangeDataType | Converts a value from one type to another |
| TestDataFromProfile | Reads a value out of a test data profile |

Most functions take a **Length**, and email functions optionally take a **Domain**. `randomEmail` with length 7 and domain `testsigma.com` produces a fresh address every run.

## Fetch an OTP from a mailbox

This is the reason most teams reach for generators, because a one-time code cannot be stored in advance.

`MailBoxFunctions.getEmailOTP` takes three inputs: a **Regex** to match the code, the **Mailbox** to read, and a **Timeout in seconds**. A six-digit code is `\d{6}` with a timeout around 45 seconds.

Related functions cover the rest of an email flow: `getLinkFromContent` pulls an activation link, `urlMatchingRegex` pulls a URL matching a pattern, and `subjectVerification` and `contentVerification` assert on what arrived.

<Aside type="note">
The timeout is how long the function waits for the email to appear. Too short and the test fails on a slow mail server rather than on a real defect. Too long and every failing run costs you that wait.
</Aside>

<Aside type="tip">
`MailBoxAliasFunctions.generateMailBoxAlias` creates a unique mailbox per run. Use it for signup tests, where reusing one address means the second run hits "email already registered".
</Aside>

## Use a custom generator

When nothing built in fits, a data generator add-on written in Java supplies your own functions. Select your add-on under **Type** in the **Data Generators** overlay instead of **Default**, and its functions appear in the same dropdowns.

## FAQs

**How do I use several runtime variables in one function argument?**

After the first variable, press the **right arrow** key twice to start the next token — `$num1`, right-arrow twice, `+`, right-arrow twice, `$num2` produces `$num1 + $num2`.
