A web test case is not limited to plain actions. Alongside natural-language steps you can add loops, conditionals, reusable groups, custom functions, and REST API calls. This page lists every step type and the shortcut that inserts it.

## Insert a step type

Click **Create Step**, then type the slash command for the type you want. The panel lists every type too, so commands are optional.

## Standard step types

These seven cover the body of most test cases.

| Step type | Command | What it is for |
| --- | --- | --- |
| Natural Language | `/` | A single action or assertion written in Testsigma's readable syntax |
| Step Group | `/stepgroup` | A reusable sequence of steps, maintained in one place |
| Create a Block | `/blocks` | A labelled group of steps inside one test case, for structure rather than reuse |
| For Loop | `/forloop` | Repeat a set of steps a fixed number of times, or once per data row |
| While Loop | `/whileloop` | Repeat a set of steps until a condition stops being true |
| Custom Function | `/function` | Call your own code when no natural-language action fits |
| Rest API | `/api` | Send a REST request as a step, then assert on or store the response |

## Conditional step types

Each of these wraps a standard type in a condition, so the wrapped step runs only when the condition holds.

| Step type | Command | What it wraps |
| --- | --- | --- |
| If Natural Language | `/if` | A natural-language step |
| If Step Group | `/if stepgroup` | A step group |
| If Custom Function | `/if function` | A custom function |
| If Rest API | `/if api` | A REST API step |

<Aside type="note">
REST API steps work in any test case, not only Rest API projects. Setting state through the API and verifying it in the browser beats driving both through the UI.
</Aside>

## FAQs

**How do I drag and drop?**

Use *Drag the element and drop on the element element*: the first element is what you drag, the second is where it lands.

**How do I upload a file?**

*Upload file test data using the element*, where the test data is a Testsigma Cloud Storage path (`testsigma-storage:/...`), a public URL (S3, Google Drive, Dropbox), or a local path. Local paths work only on your own machines through the agent — cloud labs cannot see your file system.

**How do I click something that is not always there?**

*Click on element if visible* passes when the element is visible and skips without failing when it exists but is hidden. It still fails if the element is missing from the DOM entirely; wrap the click in an *If* conditional step to survive that too.

**A text field returns nothing when I store its text.**

`<input>` and `<textarea>` keep their content in the `value` attribute, not as inner text. Use *Store the value for the attribute attribute of the element element into a variable test data* with `value`, instead of the *Store text...* step. Inspect the element: text between tags wants *Store text*, text in an attribute wants *Store the value*.

**Why clear cookies or close tabs at the start of a test?**

Long runs exhaust the test machine's disk and crash the browser, especially against apps that leak memory or open many tabs. Start tests with *Delete all cookies from the current session* and close spare windows with *Close all windows except the current window* (or the other close-window variants).

**How do I press keys that are not text?**

*Press Test Data key*, with the key's value as the test data.

| Key | Value | Key | Value |
| --- | --- | --- | --- |
| Arrow keys | `ARROW_DOWN`, `ARROW_UP`, `ARROW_LEFT`, `ARROW_RIGHT` | Backspace | `BACK_SPACE` |
| Ctrl / Alt / Shift | `CONTROL`, `ALT`, `SHIFT` | Delete / Insert | `DELETE`, `INSERT` |
| Enter / Space / Tab | `ENTER`, `SPACE`, `TAB` | Home / End | `HOME`, `END` |
| Esc / Equals | `ESCAPE`, `EQUALS` | Page up / down | `PAGE_UP`, `PAGE_DOWN` |
| Function keys | `F1` through `F12` | | |

**How do I verify a file downloaded?**

Usually, don't — verifying the link responds is enough, because what happens after the click is browser functionality, not your application's. When you truly need the file: click the download link, wait, open a new tab, go to `chrome://downloads/`, and verify the page shows the file name and **Show in folder**.

**An emailed OTP comes out wrapped in HTML.**

A regex like `>\d{6}<` grabs the digits plus the surrounding brackets. Store the OTP into a runtime variable with the **Get Email OTP** data generator, then clean it with the **Remove Special character from testdata** addon's NLP — *Remove Special char testdata1 from testdata2 and store it in runtime variable* — and use the cleaned variable.
