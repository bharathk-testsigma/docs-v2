A web test case is an ordered list of steps, and Suite gives you four routes to build them. You can write them, record them, have Copilot draft them for the current screen, or have Atto generate whole test cases from your requirements.

<Prerequisites>

- You have a web project with a feature and a scenario to file the test case under.
- The Testsigma Recorder extension is installed on Chrome, for the recording routes.
- Generative AI features are enabled in **Settings → Preferences**, for the two AI routes.

</Prerequisites>

## Choose a route

All four produce the same thing: NLP steps on the **Test Case Details** page. They differ in what you start from.

| Route | Start from | Best when |
| --- | --- | --- |
| Manually with NLPs | Nothing | You know the flow and want exact control |
| Recorder | The running application | The flow is quicker to perform than to describe |
| Copilot | The screen in front of you | You want a draft of what this page can be tested for |
| Atto | Requirements, designs, files, recordings | You are covering a feature, not a single flow |

## Create tests manually using NLPs

<Steps>

1. **Create the test case** — Go to **Create Tests → Test Cases**. In **Test Case Explorer**, expand a **Feature** and click the **+** icon beside the scenario you want.

2. **Name it** — Confirm the feature and scenario, enter a name, then click **Create**.

3. **Add the steps** — Click **Create Step** and write each one in natural language. Type `/` to pick a different [step type](/suite/web/tests/step-types/).

</Steps>

## Record steps from your application

<Steps>

1. **Start recording** — On the **Test Case Details** page, click **Record**. A new window opens.

2. **Load the application** — Enter the URL you want to test. The **Testsigma Recorder** panel activates.

3. **Perform the flow** — Interact with the page. Each action becomes a step in the background.

4. **Finish** — Click **Stop** to return to the test case and review what was captured.

</Steps>

<Aside type="tip">
Wait for the page to load fully before your first click. The extension collects locator detail in the background, and an early click records against an incomplete DOM. Press <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>F</kbd> to freeze the inspector on a dynamic dropdown.
</Aside>

## Generate steps with Copilot

Copilot works inside the recorder and suggests steps for the page you are on.

<Steps>

1. **Open the recorder** — Click **Record**, then enter your URL.

2. **Open Copilot** — Click **Testsigma Copilot** in the recorder.

3. **Generate scenarios** — Click **Generate Test Cases**. Copilot reads the current page and proposes scenarios for it.

4. **Inspect one** — Click a generated scenario to see the steps behind it.

5. **Take the steps** — Click **Add to test case** to import them into the recorder, then edit them.

6. **Finish** — Click **Stop** to return to the test case.

</Steps>

You can also type a prompt instead of taking a proposed scenario, and Copilot returns steps for what you described.

This is Copilot inside the recorder, which proposes scenarios for a page. [Copilot Mode](/suite/atto/copilot/) is the other route: it launches from the **Action Panel** and runs an existing test case as a live session you can pause and edit.

## Generate test cases with Atto

Atto works at the feature level rather than the step level, and it runs from **Atto's Home** rather than from a test case.

<Steps>

1. **Open the workspace** — Go to **Atto's Home** and click **Generate with AI**.

2. **Attach a source** — In **Generate Test Cases**, pick a source such as **Jira Requirements**, then select the project and the epics or stories.

3. **Add files** — Optionally click **Files**, then **Add Files**, **Browse**, and **Save** to attach designs, specs, or spreadsheets.

4. **Describe what you want** — Enter a prompt describing the test cases to produce.

5. **Generate** — Click **Generate with AI** and wait for the Generator agent to finish.

</Steps>

Generated cases arrive as **Pending**, and **Save to Library** files the accepted ones under **AI Generated Feature** with the status **Draft**.

<Aside type="note">
**Read existing test case library** is on by default, and it makes Atto update existing cases rather than duplicate them. Once a session starts with it on, you cannot turn it off for that session. You can only turn it on mid-session, not off.
</Aside>

## FAQs

**Why does recording need a Chrome extension?**

Modern UI frameworks build pages from generic `div` and `span` tags, so a test needs locators into the DOM to act on anything. The extension captures those locators as [elements](/suite/web/elements/) and turns your actions into steps. It does not track browsing outside the application, collect passwords or IP addresses, or modify your application's source; client-server traffic runs over a secure connection.

**The extension says third-party cookies are blocked.**

Open `chrome://settings/cookies` and select **Allow all cookies** or **Block third-party cookies in Incognito**.

**The extension cannot access local files and URLs.**

In Chrome, go to **Manage Extensions → Testsigma Extension → Details** and turn on **Allow access to File URLs**.

**Can I automate a CAPTCHA?**

Technically sometimes, practically no — CAPTCHA exists to defeat automation and keeps evolving. The industry practice is to bypass it in the test environment so tests never meet it.

**How do I get past basic authentication?**

Put the credentials in the URL of the navigate step: `https://username:password@hostname`. Use HTTPS, or the credentials travel in the clear. On Safari and mobile web this form slows each step; pass a header instead with the `testsigma.customHeaders` [capability](/suite/web/capabilities/) — `{"Authorization":"Basic <base64 of username:password>"}`.

**What is Chrome for Testing?**

An isolated, sandboxed build of Chrome used only for automation — it never touches your user data, cookies, or history. It downloads automatically once an agent registers and appears in the browser list for executions; Copilot sessions use it by default. New accounts have it out of the box; existing accounts can ask support to enable it.

**The site shows a text CAPTCHA I cannot bypass. Can a test read it?**

Yes, with the **OCR_ExtractText** addon from **Addons**. Capture two elements — the CAPTCHA image and its input field — then in the test: extract text from the image element into a runtime variable with the addon's NLP, and type that variable into the input. Prefer bypassing CAPTCHA in the test environment when you can.

**How do I log in through an authenticator app (TOTP)?**

Install the Google Authenticator browser extension, screenshot the QR code your app shows, and upload it under **Test Data → Uploads**. The extension reads the QR from the upload and generates the time-based code, which your test reads and types like any other value. Username/password, 2FA via [mailbox](/suite/web/test-data/test-data-types/) or phone number, and API-key authentication are the other supported routes.

**Can I test a Chrome extension itself?**

Yes. Get the extension's CRX file (a CRX viewer downloads it; note the extension's unique ID and its `popup.html`). Locally, put the CRX in the agent folder and pass its path in the **Extensions** desired capability; in Testsigma Lab, upload it and reference the upload. Then drive `popup.html` like any page.
