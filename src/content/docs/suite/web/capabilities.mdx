Desired capabilities customise the machine a test runs on: accepting invalid certificates, loading a browser extension, setting a geolocation or timezone, suppressing notifications. They apply per run or per machine profile, never to the test case itself.

## Capability format

Every capability is three fields.

| Field | What it holds |
| --- | --- |
| **Key** | The property name, such as `acceptInsecureCerts` |
| **Data Type** | The type of the value: boolean, String, or Integer |
| **Value** | The value itself |

## Add capabilities to an ad-hoc run

On the **Test Case Details** page click **Run**, then expand **Desired Capabilities** on the **Ad-Hoc Run** overlay and add your rows. **Delete** removes one.

## Add capabilities to a machine profile

For a plan, capabilities belong to the machine rather than the run. Open the test plan, go to **Add Test Suites & Link Machine Profiles**, click **Test machine settings** on the machine you want, then expand **Desired Capabilities** on the **Edit test machine/device profile** overlay.

<Aside type="note">
This is the difference that catches people out. A capability on an ad-hoc run applies once. A capability on a machine profile applies to every run of every plan that uses that profile.
</Aside>

## Chrome capabilities

Most Chrome options go through one key, `goog:chromeOptions`, as a String.

| To do this | Key | Value |
| --- | --- | --- |
| Accept invalid or expired certificates | `acceptInsecureCerts` | `true` (boolean) |
| Change the user agent | `goog:chromeOptions` | `{"args":["--user-agent=YOUR_STRING"]}` |
| Load a browser extension | `goog:chromeOptions` | `{"extensions":["path/to/extension"]}` |
| Load several extensions | `goog:chromeOptions` | `{"extensions":["path/to/extension1"],["path/to/extension2"]}` |
| Emulate a mobile device | `goog:chromeOptions` | `{"mobileEmulation":{"deviceName":"iPhone X"}}` |
| Disable notifications | `goog:chromeOptions` | `{"args":["--disable-notifications"]}` |
| Use a custom browser profile | `goog:chromeOptions` | `{"args":["user-data-dir=/path/to/profile"]}` |
| Allow geolocation | `goog:chromeOptions` | `{"profile.default_content_setting_values.geolocation": 1 }` |
| Set the coordinates | `geolocation` | `51.50735, -0.12776, 100` |
| Bypass download protection | `goog:chromeOptions` | `{"prefs":{"safebrowsing.enabled":"true"}}` |
| Fake camera and microphone | `goog:chromeOptions` | `{"args":["--use-fake-ui-for-media-stream"]}` and `{"args":["--use-fake-device-for-media-stream"]}` |
| Auto-select a screen to share | `goog:chromeOptions` | `{"args":["--auto-select-desktop-capture-source=Entire screen"]}` |

Geolocation needs both rows: one grants the permission, the other supplies the coordinates.

A user agent string follows the browser's own format, so copy a real one and edit it rather than composing one:

```
{"args":["--user-agent=Mozilla/5.0 (Linux; <Android Version>; <Build Tag etc.>) AppleWebKit/<WebKit Rev> (KHTML, like Gecko) Chrome/<Chrome Rev> Mobile Safari/<WebKit Rev>"]}
```

## Firefox and Edge capabilities

| Browser | To do this | Key | Value |
| --- | --- | --- | --- |
| Firefox | Accept invalid certificates | `accept_untrusted_certs` | `True` (boolean) |
| Firefox | Set the geolocation | `firefoxprofile` | The JSON profile below |
| Edge | Accept invalid certificates | `acceptInsecureCerts` | `True` (boolean) |
| Edge | Run in private browsing | `MsOptions` | `{"args":["--inprivate"]}` |

Firefox takes coordinates as a profile rather than a separate key, and it needs the testing flags as well as the location:

```json
{
  "geo.prompt.testing": true,
  "geo.prompt.testing.allow": true,
  "geo.enabled": true,
  "geo.wifi.uri": "data:application/json,{\"location\": {\"lat\": 34.052235, \"lng\": -118.243683}, \"accuracy\": 100.0}"
}
```

## Set a geolocation

There are two ways to place a run somewhere, and they answer different questions.

| Approach | Key | Use it for |
| --- | --- | --- |
| Country level | `geoLocation` | Localisation testing — content, currency, and language by country |
| Exact coordinates | `geolocation` (Chrome) or `firefoxprofile` (Firefox) | Anything that reads the browser's location API |

### By country

`geoLocation` takes a two-letter country code, such as `AR` for Argentina. It works for web and mobile web.

These 48 countries are available: Argentina (AR), Australia (AU), Austria (AT), Belgium (BE), Brazil (BR), Bulgaria (BG), Canada (CA), Chile (CL), China (CN), Croatia (HR), Czech Republic (CZ), Denmark (DK), Egypt (EG), Finland (FI), France (FR), Germany (DE), Greece (GR), Hong Kong (HK), Hungary (HU), Iceland (IS), India (IN), Indonesia (ID), Ireland (IE), Israel (IL), Italy (IT), Japan (JP), Jordan (JO), Malaysia (MY), Mexico (MX), Netherlands (NL), New Zealand (NZ), Norway (NO), Philippines (PH), Poland (PL), Portugal (PT), Russia (RU), Singapore (SG), South Africa (ZA), South Korea (KR), Spain (ES), Sweden (SE), Switzerland (CH), Taiwan (TW), Thailand (TH), Turkey (TR), Ukraine (UA), United Kingdom (GB), United States (US).

### By coordinates

Chrome needs the permission row and the coordinate row together. The three coordinate values are latitude, longitude, and altitude, so `51.50735, -0.12776, 100` is Trafalgar Square in London, and `40.783840, -73.965550, 33` is Central Park in New York.

Firefox takes it all in the profile instead, where the values are latitude, longitude, and accuracy. The example above resolves to Downtown Los Angeles; Central Park would be `{"location": {"lat": 40.783840, "lng": -73.965550}, "accuracy": 100.0}`.

Geolocation is not supported in Internet Explorer or Safari. Use [mapcoordinates.net](https://www.mapcoordinates.net/en) to find coordinates, and [mycurrentlocation.net](https://mycurrentlocation.net/) inside the run to confirm what the browser reports.

## Run in private browsing

`testsigma.privateBrowsing` launches the browser in incognito or private mode, and it works across Chrome, Firefox, and Edge rather than needing a per-browser argument.

| Key | Data Type | Value | Result |
| --- | --- | --- | --- |
| `testsigma.privateBrowsing` | Boolean | `True` | The browser launches in incognito or private mode |
| `testsigma.privateBrowsing` | Boolean | `False` | The browser launches normally |
| No capability | — | — | The browser launches normally |

Chrome, Firefox, and Edge support it. The Edge-only `MsOptions` argument above does the same thing for Edge alone.

## Basic authentication in Safari

Safari blocks credentials passed in the URL, which breaks the usual automated basic-auth login. An encoded `Authorization` header gets around it.

<Steps>

1. **Generate the header** — Use a [basic auth header generator](https://www.debugbear.com/basic-auth-header-generator) with your username and password.

2. **Open the run panel** — On **Test Case Details**, click **Run**.

3. **Pick a macOS machine** — Select the **macOS** version, **Browser**, and **Resolution**.

4. **Add the capability** — Enter `testsigma.customHeaders` as the **Key**, select **String**, and set the value to `{ "Authorization": "Basic <token>" }`.

5. **Run it** — Click **Run Now**, then check the step-level screenshot to confirm the login worked.

</Steps>

<Aside type="note">
`testsigma.customHeaders` is Safari-only. On other browsers, credentials in the URL still work.
</Aside>

## Lab and environment capabilities

These are properties of the lab, not the browser.

| To do this | Key | Data Type | Value |
| --- | --- | --- | --- |
| Cap how long a browser waits for a command | `idleTimeout` | Integer | Default `90`, range 0–1000 |
| Cap total test duration | `maxDuration` | Integer | Default `3600`, range 0–10800 |
| Set the machine timezone | `timeZone` | String | A city name, such as `Madrid` |
| Capture console logs per URL | `extendedDebugging` | Boolean | `True` |
| Enable BrowserStack visual logs | `browserstack.debug` | Boolean | `true` |
| Enable BrowserStack local testing | `browserstack.local` | Boolean | `true` |
| Capture BrowserStack browser console logs | `browserstack.console` | String | `warnings` |

<Aside type="note">
For `timeZone`, use the city alone without the continent, and replace underscores with spaces. `America/New_York` becomes `New York`. The valid names come from the [tz database list](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones).
</Aside>

`idleTimeout` and `maxDuration` exist to stop a broken test running forever. `idleTimeout` caps how long the browser waits for the next command; `maxDuration` caps the whole test. On Sauce Labs the default test limit is 30 minutes — see [Sauce Labs](/suite/integrations/test-labs/sauce-labs/).

### Console logs by lab

Which capability captures browser console output depends on the lab you run in.

| Test lab | Key | Data Type | Value |
| --- | --- | --- | --- |
| Testsigma Lab, Sauce Labs | `extendedDebugging` | Boolean | `True` |
| BrowserStack | `browserstack.console` | String | `warnings` |

[Debug](/suite/web/debug/#collect-logs-from-a-run) covers reading and downloading what they capture.

## Simulate a slow network

Network throttling is not a capability. It arrives as an add-on and works as a test step, so you can change conditions partway through a test rather than for the whole run.

<Steps>

1. **Install the add-on** — Go to **Addons → Add-ons**, find **Network Throttling** under **New & Updated Addons**, and click **Install**.

2. **Open a test case** — Go to **Create Tests → Test Cases** and open the case.

3. **Insert a step** — At the point where conditions should change, click **Step Above**.

4. **Add the NLP** — Create a step with `Simulate network to upload_speed upload speed(kbps) download_speed download speed(kbps) latency_time latency(ms)`.

</Steps>

These profiles are the standard conditions to simulate.

| Profile | Upload | Download | Latency |
| --- | --- | --- | --- |
| Regular 2G | 6.25 kbps | 31.25 kbps | 300 ms |
| Good 2G | 18.75 kbps | 56.25 kbps | 150 ms |
| Regular 3G | 31.25 kbps | 93.75 kbps | 100 ms |
| Good 3G | 93.75 kbps | 192.00 kbps | 40 ms |
| Regular 4G (default) | 384.00 kbps | 512.00 kbps | 20 ms |

## FAQs

**How do I test a legacy app that needs Internet Explorer?**

Run Edge in IE mode with the `ts.ieMode` capability (String, `true`) on a Windows machine that has IE11 present. IE mode hangs when Protected Mode differs across security zones — in `regedit`, under `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Internet Settings\Zones\1` through `\4`, create a DWORD named `2500` set to `3` in each zone so all four match.

**A permission prompt (camera, microphone, location, notifications) blocks my test.**

Grant the permission up front with a capability. Firefox: `firefoxprofile` (String) with `{"permissions.default.microphone": 1}` — the keys are `microphone`, `camera`, `geo`, and `desktop-notification`; values are 0 ask, 1 allow, 2 block; combine several with commas. Chrome: `goog:chromeOptions` (String) with `{"prefs": {"profile.default_content_setting_values.geolocation": 1}}` and the equivalent `media_stream_camera`, `media_stream_mic`, and `notifications` prefs. {/* UNVERIFIED: the legacy page's Chrome microphone example repeats the camera pref; the mic pref name used here is inferred — confirm in the product */}

**Navigation to a 3D Secure (Visa/Mastercard) page freezes the run.**

3DS pages load payment-gateway iframes whose scripts never stop, so the browser never reports the page as loaded and the driver waits forever. Set the `pageLoadStrategy` capability (String) to `none` on the run, then have your steps wait for the specific elements they need.

**Chrome's password-leak pop-up interrupts the run.**

Disable the password manager's leak detection for the session: `goog:chromeOptions` (String) set to `{"prefs": {"profile.password_manager_leak_detection": false}}`.
