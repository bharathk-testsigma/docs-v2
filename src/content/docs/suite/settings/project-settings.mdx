Four project-level lists decide how you classify and trace test cases. Requirements tie a case to something the software must do. Requirement types, test case types, and priorities are the vocabularies you sort by. All four live in **Project Settings**.

<Prerequisites>

- At least one test case exists, so there is something to classify.
- You can open **Project → Project Settings** for the current project.

</Prerequisites>

## Requirements

Mapping each test case to a requirement is what lets you show that every requirement is actually covered.

By IEEE standard 729, a requirement is a condition or capability a user needs to solve a problem or reach an objective, or one a system must possess to satisfy a contract, standard, or specification, or the documented representation of either. Requirements fall into three kinds: functional, non-functional, and domain.

### Create a requirement

<Steps>

1. **Open a test case** — Go to **Create Tests → Test Cases**. Expand a **Feature** and **Scenario**, then select a case.

2. **Open the overlay** — In the **Utility Panel**, click **Manage Test Case**.

3. **Start a requirement** — Click **Create New** in the **Requirement** field.

4. **Describe it** — Enter a **Name** and optional **Description**, select a **Type**, and set the **Start Date** and **Completion Date**.

5. **Create it** — Click **Create**.

</Steps>

### Edit or delete a requirement

In the **Manage Test Case** overlay, expand the requirement field. **Edit** opens **Edit Requirement**, where you change details and click **Update**. **Delete** asks for confirmation in the **Delete Requirement** dialog.

## Requirement types

A requirement type is the category you assign a requirement when creating it. Four ship by default.

| Default type |
| --- |
| Customer Requirements |
| User Interface Requirements |
| Functional Requirements |
| Non-Functional Requirements |

<Steps>

1. **Open the list** — Go to **Project → Project Settings**, then click **Requirement Types**.

2. **Add one** — Click **Add Type**. A blank row appears. Type the name and press <kbd>Enter</kbd>.

3. **Edit one** — Hover the type, click **Edit**, change the text, and press <kbd>Enter</kbd>.

4. **Delete one** — Hover the type, click **Delete**, then type `DELETE` and click **Delete**.

</Steps>

<Aside type="note">
A requirement type in use cannot be deleted outright. Unlink its test cases first: click **View Test Case** in the delete dialog and move each case to another type. You can also change the type from a test case's own edit page.
</Aside>

## Test case types

Test case types group cases with similar characteristics, such as functional, non-functional, or integration. They earn their keep in two places: filtering the test case list, and breaking run results down by type.

<Steps>

1. **Open the list** — Go to **Project → Project Settings**, then click **Test Case Types**.

2. **Add one** — Click **Add Type**, type the name in the blank row, and press <kbd>Enter</kbd>.

3. **Edit one** — Hover the type, click **Edit**, change the text, and press <kbd>Enter</kbd>.

4. **Delete one** — Hover the type and click **Delete**, then type `DELETE` at the prompt and click **Delete**.

</Steps>

<Aside type="note">
Deleting a type in use needs its cases unlinked first, the same as requirement types. The **Delete Confirmation** dialog offers **View Test Case** so you can reassign them.
</Aside>

### Assign a type to a test case

<Steps>

1. **Find the case** — Go to **Create Tests → Test Cases** and select it under its **Feature** and **Scenario**.

2. **Open the overlay** — Click **Manage Test Case** in the right navigation.

3. **Set the type** — Scroll to **Test Type** and pick from the dropdown.

</Steps>

## Test case priorities

Priority ranks cases by risk, coverage, or how critical the feature is. Suite ships four: **Critical**, **Major**, **Medium**, and **Minor**. You can edit them to match how your team talks, whether that is Extremely Critical through Basic, or a static-versus-dynamic split for a content system.

<Aside type="note">
New priorities can no longer be added. The four defaults remain fully usable and editable, so rename them rather than expecting to extend the list.
</Aside>
