Everything you build in Suite sits inside three nested levels. A project holds applications, and an application holds versions. Tests, elements, and data belong to one version, which is what keeps work on a beta release away from work on the shipped one.

<Prerequisites>

- You administer the project, or hold rights to edit it.
- For more than one application or version, the project allows them — a setting made at creation and editable afterwards.

</Prerequisites>

<Aside type="note">
Suite ships four sample projects, covering Web, Mobile web, Android, and iOS. They come with test cases you can run and modify, which is the fastest way to see a working project before building your own.
</Aside>

## Create a project

<Steps>

1. **Open the form** — Go to **Create New** and select **Project**.

2. **Name it** — Enter a **Project Name**, and a **Description** if you want one.

3. **Allow several applications** — Tick **Allow adding multiple applications in this project** if you need more than one. Click **Add Application**, pick an **Application Type**, and name it.

4. **Allow several versions** — Tick **Allow multiple versions for applications** if each application needs its own version history.

5. **Create it** — Click **Create**.

</Steps>

By default a project holds a single application. Custom fields you define under **Settings → Custom Fields → Projects** appear on this form too.

<Aside type="note">
Both checkboxes are easier to set now than later. A single-application project hides the **Applications** tab entirely, and you have to edit the project before you can add a second one.
</Aside>

## Edit a project

Go to **Project → Project Settings** to open the **Edit Project** dialog, change what you need, and click **Update**.

The dialog carries the project details, the multiple-application and version toggles, and the **Project Members**, **Test Case Types**, and **Requirement Types** lists. Applications and versions have their own tabs in the same dialog.

## Switch project

<Steps>

1. **Open the switcher** — Click the current project name on the **Dashboard**.

2. **Choose the target** — Select a **Project**, **Application**, and **Version**.

3. **Go** — Click **Go to project**.

</Steps>

Suite reloads on the selected project's dashboard.

## Manage applications

The **Applications** tab lists every application in the current project. It is hidden while the project holds only one, so enable multiple applications first.

### Add an application

<Steps>

1. **Open the tab** — Go to **Project Settings**, then click **Applications** in the **Edit Project** dialog.

2. **Start a new one** — Click **New Application**.

3. **Describe it** — Enter an **Application name**, **Description**, and **Version name**, then select an **Application type**.

4. **Create it** — Click **Create**.

</Steps>

### Edit or delete an application

Go to **Project Settings → Edit Project → Applications** and select the application from the dropdown. Change what you need and click **Update**.

To remove it, click **Delete Application**, then type `DELETE` in the prompt and click **Delete**.

<Aside type="note">
Deleting an application destroys every version inside it, and every test case, test data set, and upload inside those versions. The confirmation typing is the only thing standing between you and that.
</Aside>

## Manage versions

Versions exist so a release in development does not disturb the release in production. Copy version 1.0.0 to 1.0.0-beta and its ten tests come with it, while new beta-only tests stay out of the original.

### Create a version

<Steps>

1. **Open the tab** — Go to **Project Settings**, then click **Versions** in the **Edit Project** dialog.

2. **Start a new one** — Click **New version**.

3. **Describe it** — Enter a **Name**, **Description**, and a **Start Date - End Date**.

4. **Create it** — Click **Create**.

</Steps>

To bring existing work forward, turn on **Copy Data from Previous Versions** and select which models to transfer.

<Aside type="note">
Multiple versions need **Allow Multiple Versions** enabled on the project. Set it at creation, or edit the project to add it.
</Aside>

### Edit or delete a version

On the **Versions** screen, click the kebab menu beside a version and choose **Edit Version** or **Delete Version**. Deleting asks you to type `DELETE`, then click **I understand, delete this**.

### Find a version ID

API calls and CI commands need the version ID rather than its name. On the **Versions** screen, hover a version name to reveal its ID, then click **Copy**.

## Delete a project

<Steps>

1. **Open the settings** — Go to **Project → Project Settings**.

2. **Start the deletion** — Click **Delete**.

3. **Confirm twice** — Type `DELETE` in the dialog and click **Delete**, then do the same at the prompt.

</Steps>

<Aside type="note">
Deleting a project takes everything with it: every application and version, and every test case, element, test data profile, custom function, upload, requirement, test suite, test plan, run result, and environment attached to it.
</Aside>
