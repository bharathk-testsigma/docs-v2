Suite runs Windows (Lite) tests two ways. An ad-hoc run executes one test case on its own and stays out of reporting. A test plan run is the real thing. Execution is local-only: every run happens on one of your own machines through the [Testsigma Agent](/suite/installation/testsigma-agent/).

<Prerequisites>

- Testsigma Agent is registered and running on the Windows machine.
- The application under test is installed on that machine.

</Prerequisites>

## Run a single test case

<Steps>

1. **Open the run panel** — On the **Test Case Details** page, click **Run**. The **Ad-Hoc Run** panel opens.

2. **Pick the machine** — Select the **Local Test Machine** whose Agent should run the test. Cloud labs do not apply: Windows (Lite) tests run only on your own machines.

3. **Set the environment** — Select an **Environment**, and use **Manage Variables** if a value needs changing.

4. **Adjust the run** — Under **Additional settings**, set the timeouts and screenshot capture.

5. **Start it** — Click **Run Now**. The execution starts on the selected machine.

</Steps>

Page and step timeouts default to 30 seconds and cap at 120.

<Aside type="note">
An ad-hoc run produces a dry run result, kept out of your reporting. Run a half-finished test case as often as you like.
</Aside>

## Save and reuse a run configuration

Re-selecting the machine and settings every run gets old fast.

<Steps>

1. **Configure the run** — Set up the **Ad-Hoc Run** panel the way you want it.

2. **Save it** — Click **Save configuration** at the bottom right, enter a **Name**, and click **Save**.

3. **Reuse it** — Click **Saved Configs** at the top of the panel and pick it from the dropdown.

</Steps>

With a saved config loaded, the footer offers **Update configuration** as well, so you can amend it in place.

## Execute a test plan

Open the plan and click **Run Now**. Suites and their test cases execute in the order the plan defines, on the local machine each machine profile links.

<Aside type="note">
The machine must be on, unlocked, and its Agent active when the plan fires — a scheduled plan cannot wake a machine that is offline. Check **Last Successful Ping** on the **Agents** page before relying on a schedule.
</Aside>

## Run part of a test plan

A partial run executes a subset without editing the plan. That is what you want after fixing one failing area.

<Steps>

1. **Open the option** — On the test plan, open the **Run Now** dropdown and click **Partial Run**.

2. **Choose suites** — In the **Partial Test Plan Run** overlay, select **Include** or **Exclude**, then name the suites in **Test Suites to Include**.

3. **Narrow the cases** — Apply **Test Case Filters**, such as **Labels**.

4. **Start it** — Run the selection.

</Steps>

## FAQs

**My tests sit in Queued for a long time.**

On a local run this is nearly always the Agent: offline, or already busy with its maximum parallel sessions. Check the machine's **Status** and **Last Successful Ping** on the **Agents** page — see [Testsigma Agent](/suite/installation/testsigma-agent/#faqs).
