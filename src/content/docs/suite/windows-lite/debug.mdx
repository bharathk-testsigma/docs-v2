Debugging a Windows (Lite) failure is a move from symptom to cause. The result marks the step that stopped the run and holds its screenshot. The machine-side story lives with the [Testsigma Agent](/suite/installation/testsigma-agent/) that ran the test on your local machine.

<Prerequisites>

- A run has failed, and you can open its result.
- You can reach the local machine whose Agent ran the test.

</Prerequisites>

## Narrow down why it failed

Most failures come from a short list of causes. Reading the evidence in order tells you which one you have.

<Steps>

1. **Find the failing step** — Open the result. Suite marks the step that failed and stopped execution.

2. **Look at the evidence** — Check the screenshot taken at that moment against what the step expected.

3. **Compare against the element** — Open the step's element information. An element the Recorder no longer matches looks different from an application that never opened.

</Steps>

These are the usual causes, roughly in order of how often they turn up:

- The application changed, so a captured element no longer matches. Recapture it with the Recorder — see [Elements](/suite/windows-lite/elements/).
- The application did not open on the machine, or opened a different version.
- The machine was locked, or its screen state differed from when the elements were captured.
- The Agent on the machine was offline, so the run never started.
- A real bug in the application under test.

<Aside type="note">
Windows (Lite) runs execute only on your own machines through the Testsigma Agent, so the machine's state — logged-in session, screen resolution, application version — is part of every failure investigation.
</Aside>

## Check the machine side

When the result's evidence is not enough, the Agent's own logs carry what happened on the machine: whether the application launched, and what the automation session did.

<Steps>

1. **Confirm the Agent is active** — On the **Agents** page, check the machine's **Status** and **Last Successful Ping**.

2. **Pull the logs** — Collect the Agent logs from the machine. [Set the log level and send logs](/suite/installation/testsigma-agent/#set-the-log-level-and-send-logs) covers raising the level to `DEBUG` and sharing them with support.

3. **Re-run** — Fix what you found, then re-run the test case on the same machine from the result or the test case editor.

</Steps>
