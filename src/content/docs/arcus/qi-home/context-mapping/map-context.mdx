Pull requests and pushed CLI context arrive in the **Unmapped Context** view, each with an AI suggestion for where it belongs. You map an entry to a sprint or session; QI Home generates test cases from it. The flow is identical for every source.

## Before you begin

- [GitHub](/arcus/qi-home/context-mapping/connect-github/) or a [CLI tool](/arcus/qi-home/context-mapping/connect-claude-code/) is connected, and at least one entry has arrived.
- At least one sprint or Ad-Hoc session exists in the project.

## View unmapped context

<Steps>

1. **Open the view** — In QI Home, click **View** next to **Unmapped Context** in the sidebar.

</Steps>

Entries carry a badge for their source — a GitHub PR badge, or the CLI tool's badge. What each entry shows:

| Field             | GitHub PR                         | CLI context                   |
| ----------------- | --------------------------------- | ----------------------------- |
| Title             | PR title                          | Context title                 |
| Author            | PR author                         | Developer who pushed          |
| Scope             | Repository, branch, lines changed | Service area, tests explored  |
| Time              | Opened or last updated            | Pushed                        |
| **AI Suggestion** | Recommended module                | Recommended module and sprint |

## Map context to a sprint

<Steps>

1. **Start the mapping** — Click **Map to Module** on the entry.

2. **Route it** — Select the **Project**, choose **Sprint** under **Map to**, then pick the **Sprint** and its **Stories**.

3. **Confirm** — Review the **What happens next** message and click **Map**.

</Steps>

QI Home triggers generation for that sprint — new test cases, or updates to existing ones, based on the changes.

## Map context to an Ad-Hoc session

<Steps>

1. **Start the mapping** — Click **Map to Module** on the entry.

2. **Route it** — Select the **Project**, choose **Adhoc** under **Map to**, then pick an existing session or **+ Create New Adhoc Session**.

3. **Confirm** — Click **Map**.

</Steps>

## Map multiple entries at once

<Steps>

1. **Select entries** — Tick the checkboxes. A bottom action bar shows the count and **Map to Module**.

2. **Map them** — Click **Map to Module**, configure the mapping once, and click **Map**.

</Steps>

## Dismiss context

Click **Dismiss** on an entry that is not relevant to test coverage.

<Aside type="note">
  Dismissed context does not contribute to coverage and cannot be recovered from
  this view.
</Aside>

## View mapped context

The **Mapped Context** tab shows every mapped entry across all tools: **Total Mapped**, **Tests Generated**, and **Sprints Covered**, plus each entry's sprint, story, and generated case count.

<Aside type="note">
  When a developer raises a PR for work already captured as CLI context, the
  entries [unify or auto-map](/arcus/qi-home/context-mapping/overview/) — you
  map one entry, not two.
</Aside>
