The Arcus plugin for Claude Code captures your coding session as structured events: your prompts, the tools Claude runs, the files it reads and writes, and subagent boundaries. You push the captured context to [QI Home](/arcus/qi-home/overview/) with one command, and Arcus generates test cases from it.

<Prerequisites>
- Claude Code installed, ideally the latest version.
- Python 3.9 or later available on your `PATH` as `python3`. The plugin's lifecycle hooks are Python scripts, and Python ships with macOS and Linux.
- Git configured in your local environment.
- An active project in Arcus by Testsigma.
</Prerequisites>

## Install the plugin

There is nothing to build. The plugin installs from the Claude Code plugin marketplace.

In your terminal, run:

```bash
claude plugin marketplace add testsigmahq/arcus-claude-plugin
claude plugin install arcus@testsigma
```

## Log in and connect your project

{/* CONFIRM: the project ID path. No Settings navigation seen so far includes a Project page. */}

<Steps>

1. In Claude Code, run `/arcus:login`.
2. Complete the login flow in the browser, then return to Claude Code when prompted.
3. Run `/arcus:project <project-id>`, using your project ID from **Settings > Project**. To list your projects, run `/arcus:project` with no argument.
4. Start coding. The plugin captures your context in the background.

</Steps>

<Aside type="note">
Nothing is sent to Arcus until you run `/arcus:push`. Logging in and setting your project upload nothing.
</Aside>

## Map your context to a sprint

Run `/arcus:map <ticket-key>` at any point before pushing, using the Jira ticket ID for the work you're doing:

```bash
/arcus:map PROJ-123
```

Your context then arrives in QI Home already mapped to the right sprint, and the test cases generated from it trace back to that ticket. Nobody has to route it from **Unmapped Context**.

<Aside type="note">
You can push without mapping. The context lands in **Unmapped Context** and waits there with its generated tests until you resolve it to a sprint or an Ad-Hoc session.
</Aside>

## Push your context

Test cases stay on your machine until you push. Push is a guided flow, and Claude Code prompts you for each decision in order.

{/* CONFIRM: the source describes this as pushing captured context in one place and pushing generated test cases in another. */}

<Steps>

1. Run `/arcus:push`, or ask Claude Code to push the test cases.
2. Select the sprint to push into, or keep the test cases unmapped.
3. Select the story the test cases map to. This step appears only if you selected a sprint.
4. Select the module the test cases belong to. Arcus suggests one based on the test case content.
5. Set the priority for the test cases.
6. Confirm the push.

</Steps>

Arcus creates the test cases with the values you selected, and they appear in the sprint with both manual and automated steps.

<Aside type="note">
Keep the test cases unmapped when you don't yet know where the work belongs. The test cases wait in **Unmapped Context** until you resolve them.
</Aside>

## Command reference

- `/arcus:help`: lists every Arcus command with a short explanation of what it does and how to use it.
- `/arcus:login`: signs you in to Arcus so it can capture your sessions and use them for test generation.
- `/arcus:logout`: signs you out and deletes the Arcus credentials stored on your machine.
- `/arcus:project <project-id>`: shows your Arcus projects and sets one as the active project.
- `/arcus:map <ticket-key>`: links a ticket key to the current context so it routes to the right sprint.
- `/arcus:test`: generates end-to-end tests for the current repository, validates them, and offers to run them.
- `/arcus:testsigma-tests`: authors new end-to-end tests, saves them under `tests/`, validates them offline, and offers to run them.
- `/arcus:push`: uploads the test cases captured in this session to Arcus, assigned to a sprint or left unmapped.

## Pull requests for the same work

With the [Arcus GitHub App](/arcus/integrations/dev-tools/github/) installed, raising a pull request for work you captured here joins the two automatically:

- **Context still unmapped**: Arcus converts it into a GitHub context, and the Claude Code context and the pull request become a single entry in **Unmapped Context**.
- **Context already mapped**: the pull request is auto-mapped to the same sprint or Ad-Hoc session, and there's nothing more to do.
