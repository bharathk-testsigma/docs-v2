The Arcus plugin for Cursor captures your prompts, tool calls, and file changes as you work. You push the captured context to [QI Home](/arcus/qi-home/overview/) with a single command, and Arcus generates test cases from it.

<Prerequisites>
- Cursor installed.
- An active project in Arcus by Testsigma.
</Prerequisites>

## Install the plugin

Install the Arcus plugin from the Cursor marketplace.

## Log in and connect your project

{/* CONFIRM: the project ID path. No Settings navigation seen so far includes a Project page. */}

<Steps>

1. In Cursor, run `/arcus:login`.

2. Complete the login flow in the browser, then return to Cursor when prompted.

3. Run `/arcus:project <project-id>`, using your project ID from **Settings > Project**.

4. Start coding. The plugin captures your context in the background.

</Steps>

<Aside type="note">
Nothing is sent to Arcus until you run `/arcus:push`. Logging in and setting your project upload nothing.
</Aside>

## Map your context to a sprint

Run `/arcus:map <ticket-key>` at any point before pushing, using the Jira ticket ID for the work you're doing:

```bash
/arcus:map PROJ-123
```

Your context then arrives in QI Home already mapped to the right sprint, so nobody has to route it from **Unmapped Context**.

<Aside type="note">
You can push without mapping. The context lands in **Unmapped Context** and is mapped from there.
</Aside>

## Push your context

When you're done, run `/arcus:push` to upload the captured context to QI Home.

The context appears under **Unmapped Context** if you didn't run `/arcus:map`, or under the mapped sprint if you did.

## Command reference

- `/arcus:help`: lists every Arcus command with a short explanation of what it does and how to use it.
- `/arcus:login`: signs you in to Arcus so it can capture your sessions and use them for test generation.
- `/arcus:logout`: signs you out and deletes the Arcus credentials stored on your machine.
- `/arcus:project <project-id>`: shows your Arcus projects and sets one as the active project.
- `/arcus:map <ticket-key>`: links a ticket key to the current context so it routes to the right sprint.
- `/arcus:test`: generates end-to-end tests for the current repository, validates them, and offers to run them.
- `/arcus:testsigma-tests`: authors new end-to-end tests, saves them under `tests/`, validates them offline, and offers to run them.
- `/arcus:push`: uploads the test cases captured in this session to Arcus, assigned to a sprint or left unmapped.

## Pull requests for the same work

With the [Arcus GitHub App](/arcus/integrations/plugins/github/) installed, raising a pull request for work you captured here joins them automatically:

- **Context still unmapped**: Arcus converts it into a GitHub context, and the Cursor context and the pull request become a single entry in **Unmapped Context**.
- **Context already mapped**: the pull request is auto-mapped to the same sprint or Ad-Hoc session, and there's nothing more to do.
