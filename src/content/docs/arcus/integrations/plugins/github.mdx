The Arcus GitHub App sends every pull request your team raises to [QI Home](/arcus/qi-home/overview/), where Arcus generates test cases from its code changes.

<Prerequisites>
- An active Arcus project.
- Admin access to the GitHub organization.
</Prerequisites>

## Install the Arcus GitHub App

Developers don't change how they work. Once the app is installed, every pull request reaches Arcus on its own.

<Steps>

1. Go to the [Arcus GitHub App](https://github.com/apps/arcus-by-testsigma) and click **Install**.

2. Select the GitHub organization to connect.

3. Under **Repository access**, select **All repositories**, or choose specific repositories.

4. Click **Install & Authorize**. GitHub redirects you to Arcus.

5. In the **Connect GitHub** dialog, select the **Workspace** and **Project** to link this installation to.

6. Click **Connect**.

</Steps>

Pull requests raised in the connected repositories now arrive on the **Unlinked Contexts** tab of Context Management.

## Map pull requests automatically

With a tracker such as [Jira](/arcus/integrations/project-management/jira/) connected, a pull request whose title or description contains a ticket ID such as `PROJ-123` goes straight to the sprint holding that story. It never reaches **Unlinked Contexts**, and nobody maps it manually.

<Steps>

1. In the left navigation, go to **Settings > Integrations**.

2. Under **Jira**, click **Connect** and complete the Jira connection flow.

</Steps>

<Aside type="note">
A pull request with no ticket ID lands in **Unlinked Contexts** whether or not a tracker is connected. Map it manually from there.
</Aside>

## Verify the connection

<Steps>

1. In the left navigation, go to **Settings > Integrations**.

2. Under **GitHub**, confirm the organization name and repository list appear with a **Connected** status.

3. Raise a test pull request in one of the connected repositories.

4. Open **QI Home > Context Management**. The pull request appears on the **Unlinked Contexts** tab within a few seconds.

</Steps>

## Map a pull request

On **Unlinked Contexts**, click **Map to Module** on the pull request, then pick a sprint and its stories, or an Adhoc session. Arcus generates test cases from the pull request's changes, and the entry moves to **Linked Contexts**.

The full steps, including mapping several pull requests at once and discarding one that isn't relevant, are in [Context Management](/arcus/qi-home/context-management/#map-a-context).

<Aside type="note">
If the same work was captured by a coding tool plugin, Arcus joins the pull request with that session. Mapping one maps both.
</Aside>
