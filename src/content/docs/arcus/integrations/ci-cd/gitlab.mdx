A GitLab pipeline can push its JUnit results into an Arcus test run on every push to the main branch. The job verifies the report exists, then uploads it through the Arcus API.

## Before you begin

- A project with test runs exists, and you have an [API token](/arcus/settings/api-keys/).
- Your GitLab project generates test results in JUnit XML format, such as `reports/junit.xml`.

## Set the variables in GitLab

<Steps>

1. **Open the variables** — In your GitLab project, go to **Settings → CI/CD → Variables** and click **Expand**.

2. **Add three variables** — Create `TESTSIGMA_API_TOKEN`, `TESTSIGMA_PROJECT_ID`, and `TESTSIGMA_RUN_ID`, then click **Save**.

</Steps>

## Configure the pipeline

<Steps>

1. **Edit the config** — In the repository root, create or update `.gitlab-ci.yml`:

   ```yaml
   stages:
     - upload

   upload_testsigma:
     stage: upload
     image: curlimages/curl:8.10.1
     only:
       - main
     script:
       - "set -eu"
       - 'echo "Looking for reports/junit.xml ..."'
       - 'test -f reports/junit.xml || { echo "File not found: reports/junit.xml"; exit 1; }'
       - 'echo "Uploading JUnit XML to Testsigma..."'
       - 'curl --fail --show-error --location \
         --header "Authorization: Bearer ${TESTSIGMA_API_TOKEN}" \
         --form "junit_xml=@reports/junit.xml" \
         "https://test-management.testsigma.com/api/v1/projects/${TESTSIGMA_PROJECT_ID}/junit-import/test-run/${TESTSIGMA_RUN_ID}"'
       - 'echo "Upload complete."'
   ```

</Steps>

<Aside type="note">
  The project ID is in your project URL (`.../ui/projects/{Project_ID}/`) and
  the run ID in the test run URL (`.../ui/test_runs/{Run_ID}/`). Point the JUnit
  path at the report your build actually generates.
</Aside>

## Trigger the pipeline

<Steps>

1. **Push** — Commit to the connected repository. GitLab runs the workflow, and the Arcus test run updates when it completes.

</Steps>
