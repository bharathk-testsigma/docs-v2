# Testsigma Docs

Documentation for **Testsigma Suite** (test automation) and **Testsigma Arcus**
(test management), built with [Astro](https://astro.build) and
[Starlight](https://starlight.astro.build).

437 pages across two products, a frontmatter-driven API reference, Pagefind
keyword search and an AI answer assistant.

---

## Quick start

Requires **Node 22** (Astro 7 needs `^20.19 || >=22.12`).

```sh
npm install
npm run dev          # http://localhost:4321
```

Search and the Ask AI drawer both need a build first — see
[Search](#search) and [Ask AI](#ask-ai).

## Commands

| Command | What it does |
| :--- | :--- |
| `npm run dev` | Dev server on `localhost:4321` |
| `npm run build` | Production build to `dist/` (also builds the Pagefind index) |
| `npm run preview` | Serve the built site locally |
| `npm test` | Editorial budgets + API reference checks |
| `npm run build:ask-index` | Rebuild the Ask AI retrieval index (needs `VOYAGE_API_KEY`) |
| `npm run dev:ask` | Serve `dist/` **with** the real streaming `/api/ask` endpoint |
| `npm run astro ...` | Astro CLI (`astro check`, `astro add`, …) |

## Writing content

Pages are `.md`/`.mdx` under `src/content/docs/<product>/`. The file path is the
URL.

### Frontmatter contract

Beyond Starlight's own fields (`title`, `description`), this project adds an
editorial contract enforced by `npm test`:

| Field | Purpose |
| :--- | :--- |
| `pageType` | `task` \| `concept` \| `reference` \| `overview` \| `guide`. **The opt-in** — only pages that declare it are budget-checked. |
| `verified` | `YYYY-MM`, the month the UI labels and limits were last confirmed against the product. |
| `covers` | One entry per route/mode/option the page is responsible for. Each needs a matching heading — this is the only check that measures *coverage* rather than form. |
| `searchTerms` | Words readers **type** that the page doesn't itself say. Indexed but never rendered. Add one when a real query misses the page; not blanket synonyms. |
| `api` | Turns the page into an API endpoint page — see below. |

`pageType` and `verified` are optional only because the generated API pages and
some ported pages predate the contract.

### Authoring components

| Component | Use for |
| :--- | :--- |
| `PlatformTabs` | Content differing only by platform (Web/Mobile/Salesforce/Windows) or language. Platforms are **tabs, not separate nav branches**. |
| `DocCard` | Cards on section overview pages. |
| `Prerequisites` | The bordered prerequisites box — deliberately distinct from note/tip/caution asides, because a prerequisite is a gate, not an aside. |

## Navigation

Both products live in **one** Starlight `sidebar` array, each under a top-level
group. `starlightRouteData.ts` unwraps whichever group matches the URL, so the
reader only ever sees one product's tree — never a "Suite"/"Arcus" wrapper node.
Within Suite it further splits the API reference into its own nav.

Two separate `sidebar` arrays isn't an option: Starlight takes exactly one.

Suite's nav is hand-authored in `sidebar-suite-v2.mjs`; Arcus's uses Starlight's
`autogenerate`. That's a known inconsistency — `humanize()` in the route
middleware exists purely to fix directory-name labels (`REPORT-IMPORTS`) that
autogeneration produces.

## API reference

Endpoint pages are **pure frontmatter**. The `api:` block is the single source of
truth, and `ApiMarkdownContent.astro` renders the method badge, parameter tables,
and the cURL / JavaScript / Python samples — all *derived* from
`method` + `path` + body, so samples cannot drift from the spec.

```yaml
api:
  method: POST
  path: /test_plans/{id}/run
  baseUrl: https://app.testsigma.com/api/v1
  pathParams:
    - { name: id, desc: Test plan ID }
  response: { ... }
```

**Regional hosts:** never hardcode one. `src/data/regions.ts` is the only place a
host may be declared; pages keep the canonical US host and a client-side picker
rewrites it. Adding a region is a one-line change there.

## Search

Pagefind indexes the **built** HTML, so search only works after `npm run build`.

The `prebuild`/`postbuild` hooks exist for a real reason: Pagefind writes into
`dist/`, but `astro dev` serves `public/`. `postbuild` copies the index into
`public/` so search works in dev; `prebuild` clears it first, otherwise Astro
copies the stale index into `dist/` before Pagefind regenerates and old
content-hashed fragments pile up in the deployed output. `public/pagefind/` is
gitignored.

## Ask AI

The "Ask" button opens a drawer that answers from the docs: the question is
embedded (Voyage AI), matched against a prebuilt vector index, and answered by
Claude with streaming citations.

```
scripts/build-ask-index.mjs   →  public/ask-index.bin + .meta.json  (committed)
api/ask.ts                    →  retrieval + streaming answer
api/ask-feedback.ts           →  thumbs up/down logging
```

Set both keys in `.env` (see `.env.example`) — they are **server-side only** and
never shipped to the browser:

```sh
VOYAGE_API_KEY=      # embeddings
ANTHROPIC_API_KEY=   # answers
```

Full local run with the real streaming endpoint:

```sh
npm run build && npm run dev:ask
```

**Without the keys the site still works** — the drawer falls back to Pagefind
keyword search, and the button never breaks the page.

**The index is committed and rebuilt by hand.** Re-run `npm run build:ask-index`
whenever content changes; nothing detects staleness automatically, and a stale
index makes the assistant answer from pages that have moved or no longer exist.

## Tests

```sh
npm test
```

- **`docs-budgets`** — editorial limits from the writer rules: median sentence
  length, intro length, callout count, prose cap per `pageType`, and `covers`
  coverage. Set `VERBOSE=1` for the full per-page table.
- **`api-reference`** — walks the built HTML and asserts every endpoint page
  actually renders the method, URL and samples its frontmatter declares. **Run
  `npm run build` first.**
- **`ask-index`** — unit checks for the index builder's chunking and Markdown
  stripping.
- **`ask-golden`** — retrieval quality against golden questions. Skipped unless
  `VOYAGE_API_KEY` and a built index are present (`npm run test:ask`).

### Known failures on `main`

`npm test` currently reports **4 failures**, all pre-existing:

| Failure | Cause |
| :--- | :--- |
| `api-reference` | Tooling, not content — the suite imports `src/data/regions.ts`, which bare `node --test` cannot load (`ERR_UNKNOWN_FILE_EXTENSION`). Runs green with `node --import tsx --test`. |
| `W-04` (248 pages) | Intro before the first heading outside the 30–45 word band. |
| `W-34` (374 pages) | Pages without 2–4 `Related` links. |
| `T-28` (7 pages) | `UNVERIFIED` markers still in the content, awaiting SME confirmation. |

The last three are editorial debt across most of the corpus, not regressions.

## Base path

The site is served under **`/docs-new/`**, not the domain root, so `base` is set
in `astro.config.mjs` from the single constant in `src/lib/site-config.mjs`.
**Cutover to `/docs` is a one-line edit there.**

This cannot be pushed down to Apache. A proxy can rewrite the *request* path, but
the built output carries absolute URLs, and some are assembled at runtime from
`import.meta.env.BASE_URL` — Pagefind's `bundlePath` in `Search.astro` is baked
into the JS bundle, where no response rewriting reaches it.

Four things need the base applied by hand, because Astro does not do it:

| | Handled by |
| :--- | :--- |
| Hand-written `href`/`src` in components | `withBase()` from `src/lib/base.ts` |
| `pathname` comparisons (`startsWith('/arcus/')`) | `stripBase()` — including the **client-side** `product()` in `ask-shared.ts` |
| Absolute links authored in markdown (483 of them) | `rehypeBaseLinks` plugin, at build time |
| `href` props on MDX components (`<DocCard/>`) | The component itself — JSX props never reach rehype |

Redirect **values** in `astro.config.mjs` also need it: Astro prefixes redirect
keys with `base` but not their destinations.

Authors keep writing plain `/suite/...` links — the plugin handles the prefix, so
content stays portable across the cutover.

## Deploying

`.github/workflows/manual.yml` — manual dispatch, pick
`staging` or `production`.

```
build static site → bake into httpd image → push to ECR
  → bump image tag in devops-helm → ArgoCD syncs to EKS → invalidate CloudFront
```

The site is served under **`/docs-new/`**. The ALB ingress routes
`website.testsigma.com/docs-new` straight to this service, so the website's own
Apache is not in the path and the `website` repo needs no change. The workflow
never talks to the cluster directly — the commit to `devops-helm` is what
triggers the rollout.

### httpd configs

Two of them, following the same split every app repo here uses:

| File | Used by |
| :--- | :--- |
| `apache2/docs-new.conf` | **Production.** Baked into the image by the `Dockerfile` as `conf/extra/docs-new.conf`. Serves `/docs-new/`, sets cache headers, and wires Astro's 404 page. |
| `httpd-conf/docs-new/rules.conf` | **Local dev only.** Mounted into the shared dev httpd by `dev-setup/docker/httpd/docker-compose.yml`; proxies `/docs-new` to `npm run dev` on 4321, so edits are live. |

The dev rules deliberately set no `ProxyPreserveHost`: every app's rules are
`Include`d into the **main** server config with no vhosts, so that directive is
server-wide and would change proxying for every other app in the container.

### Not yet in place

Everything in this repo is done (`Dockerfile`, `apache2/docs-new.conf`, `base`,
the workflow). What is left is infrastructure:

| Needed | Where |
| :--- | :--- |
| ECR repos `docs-v2-staging` / `docs-v2-production` | AWS |
| OIDC trust policy extended to this repo | AWS — the role currently trusts `TestsigmaInc/website` only. |
| Repo secrets + GitHub App install | This repo's Actions settings. |
| `.Deployments.docsNew` on the **`prod`** branch | `devops-helm` — the change is currently only on `staging`. |

**Vercel** is also configured (`vercel.json`) and is the only target where the
Ask AI API runs as a serverless function. On the httpd/EKS path there is no
serverless runtime, so Ask AI degrades to keyword search unless `/api/ask` is
proxied elsewhere.
